# BulbuLator — Аудио-движок: архитектура под ВСЕ форматы (вкл. lossless)

> Создано 2026-07-05. Синтез трёх сворм-отчётов (общие плееры mpd/PortAudio/mpv/SDL · диджейский софт Mixxx/CDJ-3000/Serato/Traktor · Zynq dual-core bring-up). Цель владельца: **проигрывание точное и стабильное как у экстра-профессиональной техники; НИЧТО в браузере (скан, config save, отрисовка) не рвёт фоновый звук; играют ВСЕ форматы, включая lossless; VBR+CBR идеально; архитектурно правильно.** Связано: [[HANDOVER]], [[session-step14-4-dn-browser]], [[STEP_14_SPEC]].

## Доктрина (единое правило всех профи-плееров)
RT-поток/колбэк аудио ОБЯЗАН отдать DAC один буфер до жёсткого дедлайна — каждый буфер, всегда. Промах = слышимый щелчок (xrun/underrun). Всё остальное (браузинг, декод, анализ, отрисовка, загрузка) держится ВНЕ этого потока и общается через уже-в-RAM буферы по lock-free FIFO. **Аудио-поток читает только сэмплы, которые уже в RAM.** В колбэке ЗАПРЕЩЕНО: malloc/free, блокировки, файловый I/O, любой вызов с непредсказуемым временем. (Bencina RT101; PortAudio callback contract; Mixxx Developer-Guide-Engine.)

Часы: **устройство (DAC) — мастер.** Никто не пейсит по стенным часам. Для чистого аудио-плеера второго потока нет → синхронизировать не с чем, единственная задача — «держать FIFO непустым».

## Наша архитектура (3 слоя, машино-агностично)
```
SD --f_read--> [compressed buf] --декодер--> [PCM ring rb_buf ~2.7с] --ISR--> [fabric FIFO 256] --> DAC 47996Гц
              (CPU0, продюсер)              (общий, sink-rate)      (консюмер)
```
- **CONSUMER** = 1мс SCU-timer ISR (`player_isr_tick`): pop кольца → фабричный FIFO. Fade Q8 per-sample. НИКОГДА не трогает SD.
- **PRODUCER** = главный цикл (`player_pump`): декод/ресемпл в кольцо квантами. Вся тяжёлая работа (SD, декод, компакция) — только тут, сталл переживается кольцом.
- **RING** = `rb_buf[131072]` SPSC, packed {R<<16|L}. Формат-агностичен: PCM есть PCM, любой кодек (MP3/WAV/PSG/FLAC/Opus) сюда сливается одинаково. Ресемпл к PLAYER_SR=47996 делается ОДИН раз в продюсере (speexdsp q7) → в кольце и в FIFO частота совпадает by construction, дрейфа нет.

## ✅ Фаза P0 — СДЕЛАНО (v0.14.12, на железе 2026-07-05)
**Баг:** MP3 ускорялся ~0.5с раз в ~30-40с. **Корень:** SLIP по стенным часам (`g_t0 += miss` в ISR) — при SD-сталле кольцо проседало, консюмер «прыгал» временем = ускорение. Плюс продюсер добирал кольцо «дриблингом» (`≤4 кадра/вызов` в `mp3_refill`, 2×`stream_produce`) — не мог восстановиться за один проход после сталла.

**Фикс:**
1. **Консюмер FIFO-тактируемый**: `while(!(AUDIO_STAT & FULL)) push`. Частота слива фабричного FIFO (= DAC 47996Гц) — ЕДИНСТВЕННЫЕ часы. `XTime`/`g_t0`/`due`/`PLAYER_LEAD`/**SLIP удалены**. На пустом кольце → **тишина** (s=0), НЕ прыжок и НЕ реплей устаревшего слова. Fade вниз на кромке (без щелчка). `g_samples` (elapsed-часы) считает только реальные сэмплы. Циклы ISR жёстко ограничены (budget=260 ≈ глубина FIFO) — не зависнут на битом STAT.
2. **Продюсер догоняет до high-watermark**: `mp3_refill` держит НЕПРОЧИТАННЫЕ (`D_len-D_pos`) до 3/4 DCAP (важно: watermark на непрочитанных, не на `D_len` — тот монотонный курсор записи, иначе ложный EOF); `player_pump` льёт кольцо до 7/8 (`RB_HIGH_WM`) за проход (guard=64). Один pump после сталла восстанавливает весь дефицит.

**Ключевой факт (Mixxx-отчёт, снимает страх):** Zynq **xsdps НЕ глушит прерывания** — это ADMA2 + polling статус-бита, а не PIO-кормёжка FIFO с `cpsid`. → 1мс таймер-ISR тикает СКВОЗЬ f_read/f_write, фабричный FIFO (5.3мс) не голодает во время скана. Поэтому глюк был ТОЛЬКО в продюсере/кольце (починено), а не в консюмере.

## ➡️ План дальше (по нарастанию, «до 150%»)
- **P1 — высший GIC-приоритет таймер-ISR** (1 строка в `audio_irq_init`: `XScuGic_SetPriorityTriggerType(&g_gic, XPAR_SCUTIMER_INTR, 0x00, 0x03)`). Сейчас таймер — единственный IRQ, так что польза появится при добавлении др. источников (IRQ-SD/PS2). Дешёвая страховка.
- **P2 — предзагрузка всего файла в RAM** (CDJ-3000 «long buffer»; ~246МБ DDR свободно). PSG (КБ) и MP3-сжатый (5мин@320=12МБ) — целиком; WAV — целиком если влезает (5мин CD≈52МБ), иначе стрим-фолбэк 64КБ. `psg_byte`/`stream_byte`/`M_fill` читают из RAM. **Убирает SD из тракта ДАННЫХ аудио.** Загрузку прячем под fade-in. ВАЖНО: preload сам по себе НЕ спасает от блока главного цикла при скане/save (это отдельный SD-op) → нужен ещё P3.
- **P3 — кооперативный `player_pump()` в длинных циклах** (bare-metal замена воркер-потоку Mixxx `CachingReaderWorker`): в цикле `f_readdir` каждые 32 записи + до/после `config_save` `f_write`. Ограничивает сталл продюсера одним квантом; кольцо перестаёт быть единственной защитой. С P2 pump тут = чистый CPU (0 SD) → безопасно.
- **P4** — watermark уже сделан (P0). Опц. поднять кольцо до 4-5с (+1МБ) если откажемся от P3.
- **P5 (later)** — (a) фабричный FIFO 256→1024 (дешёвый BRAM), (b) декод во втором, низкоприоритетном таймер-ISR (нужен GIC-nesting), (c) 2-е кольцо+FIFO+AUDIO_CTRL бит для cue/preview (модель Master/Headphones Mixxx).

## 🎯 CPU1 = выделенное аудио-ядро (Tier-2 AMP) — под lossless/DSP
**Когда нужно:** FLAC/lossless/ресемпл/эффекты (растёт CPU декода, UI на CPU0 крал бы циклы), ИЛИ несколько потоков, ИЛИ когда встанет софт-эмуляция-ярус (ATM/EVO/TSConf на core1 — тогда AMP-каркас уже готов, платит дважды). До этого — P0-P3 на одном ядре скорее всего достаточно.

**Механика (XAPP1079, подтверждено первоисточниками):**
- Поднять CPU1: `Xil_Out32(0xFFFFFFF0, CPU1_ENTRY); Xil_DCacheFlushRange(0xFFFFFFF0,4); dsb(); sev();` (CPU1 сидит в WFE-загоне в OCM, читает магию по 0xFFFFFFF0). Фолбэк: пульс `A9_CPU_RST_CTRL` 0xF8000244 (unlock SLCR 0xF8000008=0xDF0D).
- BSP CPU1 собрать с **`-DUSE_AMP=1`** (boot.S пропускает SCU-invalidate/L2-init — их делает ТОЛЬКО CPU0, иначе портит CPU0). Свой стек/VBAR/TTBR0/MMU. `ACTLR.SMP=1` на обоих (стандартный boot.S ставит).
- Партиционировать DDR в линкерах: код CPU0, код CPU1, shared-блок, файл-буфер — не пересекаются и не задевают видео-FB / OSD-канвас 0x0F800000.

**Разделение труда:**
- **CPU0**: UI, браузер, SD (FatFs/xsdps — единственный владелец, xsdps не multi-core-safe), OSD, конфиг. + Новое: читает выбранный файл в **shared compressed-буфер** DDR (весь для мелких; кольцевой read-ahead для больших MP3/WAV). НЕ декодит, НЕ трогает FIFO.
- **CPU1**: весь декод (minimp3/AYUMI/WAV/FLAC…) из shared-буфера → **CPU1-ЛОКАЛЬНОЕ PCM-кольцо** → фабричный FIFO 0x4000007C. **Не трогает SD.** Чистый poll-цикл, пейс по FIFO-not-full (те же P0-часы). PL AXI GP0 виден обоим (Device mem), сериализуется на слейве — блокировка не нужна пока CPU1 владеет аудио-регистрами, CPU0 — OSD-регистрами (непересекающиеся offset). Приватный таймер CPU1 @0xF8F00600 банкованный (PPI ID29).

**Когерентность (ключевой ход — минимизировать шаринг):**
- **PCM-кольцо НЕ пересекает ядра** (продюсер=декод CPU1, консюмер=FIFO-feed CPU1) → ~90% когерентного трафика убито, сложный высокочастотный SPSC — внутриядерный.
- **Control-block** (флаги/индексы/статус, мелочь) → **non-cacheable** `NORM_NONCACHE 0x11DE2` (`Xil_SetTlbAttributes`). Всегда когерентен, без выравнивания-ловушек.
- **Compressed файл-буфер** (CPU0 пишет, CPU1 много читает) → cacheable + **явное обслуживание**: CPU0 `Xil_DCacheFlushRange(chunk)` → публикует индекс (`dmb()`); CPU1 читает индекс (`dmb()`) → `Xil_DCacheInvalidateRange(chunk)` → декод. НЕ требует SMP/shareable корректности (проект исторически D-cache OFF из-за xsdps-бага; переход на CPU1 = момент включить D-cache ON, он же нужен для цветного OSD и софт-яруса). Альтернатива: cacheable+shareable `NORM_WB_CACHE 0x15DE6`+SMP на обоих → SCU держит когерентность без обслуживания (чище, но зависит от SMP+shareable+SCU). Сначала явное обслуживание, потом апгрейд.
- Барьеры: продюсер data-then-index (`dmb()`), консюмер index-then-data (`dmb()`). Линия кэша A9 = 32Б → cacheable регионы выровнять/паддить на 32.

**Shared control-block** (пример): cmd/cmd_seq/format/volume/seek + compressed-SPSC (src_base/cap/total/wr/eof) + обратно (state/ack_seq/pos_ms/rd/underruns). Хэндшейк = seq-счётчик (SPSC, без мьютекса): CPU0 пишет поля→cmd→cmd_seq++→dmb; CPU1 видит cmd_seq!=ack_seq→применяет→ack_seq=cmd_seq→dmb.

## 🔌 Кодек-плагин интерфейс (для «все форматы»)
Сейчас `g_fmt` switch (PSG/WAV/MP3) + `src_next()` диспетчер — рудиментарный вариант. Правильно: интерфейс `open/read_frame/close/duration/samplerate/seek`, любой кодек — реализация. Кольцо и ресемплер уже формат-агностичны → добавить FLAC/Opus/Vorbis/трекеры (libxmp/GME/pocketmod/cRSID/PT3) = реализовать интерфейс + читать из абстрактного «compressed byte source» (не прямой f_read — под CPU1-сплит). **VBR+CBR MP3 уже точны**: длительность из Xing/Info/VBRI up-front (`mp3_parse_duration`), как mpg123/ffmpeg. Движок «все форматы» = ГИБРИД (bare-metal декодеры + Linux-ZXTune потом) — см. память.

## 🔴 Наблюдения на железе + фиксы (2026-07-06)
1. **Старт/стоп щелчок (low-freq pop)** — сворм-анализ (анти-поп агент a2496916). Корень: DC-blocker = ПОСЛЕДНЯЯ ступень тракта (`bulbulator_zx_ddr_top.v:895-918`); любой DC-шаг на его входе → затухающий LF-транзиент (τ≈5.3мс). **СТОП:** 256-сэмпловый a_gain-fade РОВНО маскируется 256-глубоким фабричным FIFO → на срезе провод несёт ещё ПОЛНУЮ амплитуду, HOLD-LAST морозит её DC-пьедесталом → громкий поп ∝|V0|. **СТАРТ:** idle-DC фабрики (F) кроссфейдится через blocker → thump ∝F.
   - **✅ 4a СДЕЛАНО (v0.14.18, SW-only, без ресинтеза):** `player_stop` теперь ДРЕНИРУЕТ фабричный FIFO (ждёт `AUDIO_STAT` empty) ПЕРЕД снятием mux — как уже делает EOF-путь. Fade-рампа доходит до DAC (V0→0), FIFO пуст → следующий `track_arm` без stale-фрагмента (убирает и старт-поп). Музыка НЕ режется. **✓ v0.14.18 на железе: громкий поп УШЁЛ; остаётся ТИШЕ = остаточный idle-DC фабрики (F) → нужен 4b (RTL) на следующем ресинтезе.**
   - **⏳ 4b (RTL, 1 ресинтез) — остаточный F-thump:** per-source DC-block на ФАБРИЧНОЙ ноге ДО кроссфейда (тот же single-pole HPF, `top.v` после стр.819 + замена `left16_a1/right16_a1`→dc-blocked в 854-855). Делать при следующей сборке битстрима. Альтернатива 4c = output soft-mute (нов. бит `AUDIO_CTRL` + ARM-секвенс mute→switch→unmute) — гарантированный «молоток».
   - Опц. полировка: EOF decay-tail (15/16 гео, `player.c`) → линейный/raised-cosine за 256 сэмплов.
2. **Срыв темпа: VBR ~1:15 (v0.14.17) И CBR ~5:00 (v0.14.18) — НЕ формат-специфично, ОБЩИЙ underrun** — НЕ speed-up (убит P0), а **RING UNDERRUN** (случайные SD read-stalls / хронический дефицит продюсера). **P2 (RAM-preload → SD вне аудио-тракта) = ДЕФИНИТИВНЫЙ фикс.** → короткий провал/заминка (VBR-пик быстрее осушает кольцо). Кандидаты: хронический near-underrun+VBR-пик; SD read-stall 100-160мс; долгий блок главного цикла (скан/редроу). Диагностика: JTAG-чтение **`g_underruns`** (инструментировано в P0). **ФИКС: P2 (RAM-preload → SD вне аудио-тракта) + P3 (кооп-`player_pump` в длинных операциях) + опц. глубже кольцо/read-ahead.** Делать в аудио-hardening проход.
