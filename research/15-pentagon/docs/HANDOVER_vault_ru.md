## 1. ЧТО УЖЕ СДЕЛАНО И ПОЛНОСТЬЮ РАБОТАЕТ (v0.14.26)

### 🎵 АУДИО — Идеальное воспроизведение (Pro-DJ Polish)
- **Абсолютно бесшовный переход (Gapless):** При смене трека (вручную или автопереход) мультиплексор звука ПЛИС **не отпускается**, а продолжает удерживаться плеером, посылая тишину. Это полностью устранило двойной щелчок (thump) и паразитный писк от ZX Spectrum при переходе между треками (`arm/player.c`).
- **Сглаживание окончания трека (Raised-Cosine Declick):** Вместо резкого геометрического спада громкости в конце трека теперь используется 256-сэмпловый квадратичный спад (похожий на окно Ханна, с нулевой производной в начале и конце), гарантирующий тишину без обрезки сэмплов.
- **Мгновенный CDJ-Старт и Фоновая Предзагрузка:** В `opt_items` добавлена настройка `MP3 PRELOAD`. Если она включена (`YES`), плеер мгновенно стартует трек, вычитав синхронно только первые 256 КБ (занимает <25 мс). Остальные 32 МБ дочитываются в ОЗУ прямо во время воспроизведения невидимыми кусками по 64 КБ (`guard=2` в `mp3_refill`), абсолютно не нагружая процессор и сохраняя интерфейс мгновенно отзывчивым.
- **Аппаратный DC-Blocker (RTL `bulbulator_zx_ddr_top.v`):** Постоянная составляющая напряжения (idle-DC), которую генерирует простаивающий бипер ZX Spectrum, отсекается однополюсным ФВЧ (HPF, fc~30Hz) *до* аппаратного кроссфейдера. Щелчков при старте и стопе больше нет.
- **Плавная громкость по F9 (RTL Volume Slew):** Регулировка громкости теперь происходит не мгновенными скачками амплитуды, а плавно догоняется аппаратно (slew rate `vgain`) по 1 LSB за такт. Треск и шорохи (zipper-noise) при изменении громкости исчезли навсегда.
- **Телеметрия:** Фантомные счетчики усадок `g_underruns` при остановке трека исправлены (учитывается флаг `!prod_done`). Буфер работает идеально.

### 🖥️ ВИЗУАЛЬНЫЙ UI — Клон DOS Navigator / Turbo Vision
- **MenuBar (F9):** Внедрена система данных `MenuItem` / `Menu` / `BarItem`. По нажатию F9 открывается верхнее меню. Клавиши Влево/Вправо плавно перемещают курсор, мгновенно разворачивая соседние списки (sticky-режим). Вверх/Вниз перепрыгивает через разделители (сепараторы).
- **Отсутствие мерцания (Flicker-Free):** Навигация по спискам перерисовывает строго только старую и новую строку меню (`menubox_draw_row`). Фон списка файлов сзади больше не перерисовывается, что делает скроллинг абсолютно плавным.
- **Трехмерные Кнопки (3D Buttons):** Диалоговые кнопки (`[ OK ]`, `[ Cancel ]`) теперь рисуются псевдографикой с объемной тенью (символы `0xDC` / `0xDF` шрифта CP866). Дефолтная кнопка подсвечивается бирюзовыми указателями `►` и `◄` и имеет инверсный (синий) фон.
- **Исправление багов управления (v0.14.26):**
  - Удален «быстрый сканер букв» для навигации по меню, который ложно срабатывал на сырые префиксы расширенных кнопок (вызывая прыжки влево/вправо при скроллинге вверх/вниз).
  - В модальном цикле `get_keysym_blocking()` добавлен полноценный аппаратный Debounce (задержка 20 мс) и фильтр префиксов `0xE0` / `0xF0`.
  - При закрытии меню по `Esc` буфер FIFO клавиатуры ПЛИС аппаратно вычищается (`kbd_flush`), а краевой детектор `mkey` сбрасывается в 0, что устранило знаменитый баг «зацикливания и мерцания F9/Esc».

## 2. ГЛАВНАЯ ПРОБЛЕМА СЕЙЧАС (Зачем нужна Фаза 4)
Текущая обработка клавиатуры в `arm/loader_main.c` — это "лапша". Главный цикл (`for(;;)`) читает напрямую из регистра `KBD_DATA`. Если открыто меню, оно перехватывает управление и читает этот же регистр в блокирующем цикле (`get_keysym_blocking()`). 
Из-за этого:
* **Невозможно сделать ввод текста:** Для переименования файла по F6 (Rename) нам нужен компонент `InputLine`. Чтобы он работал, система должна передавать готовые ASCII символы с учетом зажатых Shift / CapsLock, а не сырые PS/2 скан-коды.
* **Теряются нажатия:** Если одно прерывание не успело отработать, `KBD_DATA` переполняется или события «нажата-отпущена» рассинхронизируются.
* **Смешение логики:** Модальные окна приходится рисовать грязными хаками, сохраняя состояние браузера (`prior_browser_on`).

## 3. ПЛАН ДЛЯ СЛЕДУЮЩЕГО АГЕНТА: Рефакторинг Событий (Event Queue)
Следующий разработчик должен полностью оторвать UI от сырого чтения `KBD_DATA` и реализовать классический Event Loop (по примеру Turbo Vision `TEvent` или SDL `SDL_Event`).

### Архитектурный Чертёж (Blueprint) для Интеграции:

**Шаг 1: Структура События (`dn_event_t`)**
Создать структуру, которая будет передаваться из драйвера в UI.
```c
typedef struct {
    uint16_t keycode;    // Внутренний сканкод (например, K_UP, K_F9, K_ENTER)
    uint8_t  ascii;      // Готовый печатный символ (уже с учетом Shift!), например 'A', 'a', '!'
    uint8_t  modifiers;  // Битовая маска: 1=Shift, 2=Ctrl, 4=Alt
    uint8_t  is_release; // 1 = клавиша отпущена (KeyUp), 0 = нажата (KeyDown)
} dn_event_t;
```

**Шаг 2: Кольцевой Буфер (Event Queue)**
Создать массив `dn_event_t kbd_event_queue[32]` с индексами чтения и записи.

**Шаг 3: Низкоуровневый Драйвер-Поллер (`kbd_driver_poll`)**
Забрать всё чтение `KBD_DATA` из основного цикла и поместить его в функцию-поллер (или прерывание ISR), которая вызывается максимально часто. Эта функция содержит Конечный Автомат (State Machine):
- Читает PS/2 байты.
- Помнит, пришел ли префикс `E0` (расширенные кнопки) или `F0` (отпускание).
- Управляет состоянием `g_shift_held`, `g_ctrl_held`, `g_alt_held`.
- **ASCII Трансляция:** Имеет две таблицы (без шифта и с шифтом) для конвертации сырого PS/2 `0x1C` в `a` или `A`.
- Формирует `dn_event_t` и делает `push` в кольцевой буфер.

**Шаг 4: Центральный Диспетчер Приложения (`get_event`)**
Заменить все прямые чтения `KBD_DATA` в `loader_main.c` на:
```c
dn_event_t ev;
if (get_event(&ev)) {
    if (ev.is_release) continue; // Пока UI реагирует только на нажатия
    switch (ev.keycode) {
        ...
    }
}
```

**Шаг 5: Ввод текста (F6 Rename)**
Как только события полетят корректно, создать класс модального окна `InputLine`. Если `ev.ascii != 0`, добавлять символ в строку. Если `K_BACKSPACE` — удалять последний. Если `K_ENTER` — вызывать функцию FATFS для переименования файла (`f_rename`).
