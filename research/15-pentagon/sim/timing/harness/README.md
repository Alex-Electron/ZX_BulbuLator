# Стенд целой машины Atlas в xsim (`tb_zx.sv`)

Шаг 0 работ по таймингам 48K: **только измерения**, RTL под `sources/` и `cores/` не тронут.
Стенд оборачивает модуль `main` (`sources/atlas_core/main.v`) со всеми зависимостями ровно в том
составе, в каком их читает `sources/build/build.tcl` для цели Atlas (строки 17-70), без HDMI,
топа `bulbulator_zx_ddr_top.v` и `clock_zx.v` (тактовые разрешения генерирует сам стенд).

Каталог: `research/15-pentagon/sim/timing/harness/`.

| файл | что это |
|---|---|
| `tb_zx.sv` | стенд: такты, машина, память, счётчики, плюс-аргументы, проверки |
| `run.sh` | компиляция (xvhdl/xvlog/xelab) и запуск xsim; аргументы `NAME=VAL` уходят в `-testplusarg` |
| `verify_all.sh` | семь приёмочных прогонов параллельно (каждый в своём `wd/<имя>`), сводка |
| `prog/marker.asm`, `prog/build.sh` | проверочная программа Z80 и её сборка под каждый ORG (`marker_8000.bin`, `marker_5000.bin`) |
| `gen/wd1793_xsim.sv` | генерируется `run.sh` из `sources/wd1793.sv` при каждой сборке (см. гочи), в сборку Vivado не класть |
| `logs/` | логи компиляции и всех приёмочных прогонов (числа ниже взяты из них) |
| `rom128.hex` | симлинк на `sources/build/rom128.hex` (страницы 0 = 128-меню, 1 = 48 BASIC) |

## Как собрать и запустить

```sh
ssh thinkpad
cd ~/bulb-v13/research/15-pentagon/sim/timing/harness
./run.sh --build MACHINE=48 RUNUS=45000          # собрать снапшот и прогнать 45 мс 48К с настоящим ПЗУ
./run.sh MACHINE=PENT PROG=prog/marker_8000.bin ORG=8000 CHECKMARK=1 RUNUS=100000
./run.sh MACHINE=128 RUNUS=5000 PCTRACE=40      # первые 40 выборок команд
./verify_all.sh                                  # все приёмочные прогоны (сначала ./run.sh --build)
```

`run.sh` сам делает `source settings64.sh`, создаёт симлинк `rom128.hex`, при отсутствии `xsim.dir/tb_zx`
собирает снапшот. `--build` пересобирает принудительно, `--debug` добавляет `--debug typical`
(волны), `--sim-only` запрещает сборку, `--wd=<имя>` запускает в отдельном каталоге `wd/<имя>` со
СВОЕЙ копией снапшота (нужно для параллельных прогонов, см. гочи). Лог каждого прогона ложится в
`logs/run_<аргументы>.log`, последняя строка `wall: N s`.

Список файлов в `run.sh` = `build.tcl` цели Atlas: T80 (`zx/src/T80/{T80_Pack,T80_Reg,T80_MCode,T80_ALU,T80pa}.vhd`
+ НАШ форк `sources/t80_bulb/T80.vhd`; апстримный `zx/src/T80/T80.vhd` НЕ читается), `zx/src/JT49/*.v`,
`zx/src/saa1099.sv`, `wd1793.sv` (через `gen/`), `atlas_core/{main,video,memory}.v`, `zx/src/cpu.v`,
`turbosound_bulb.v`, `zx/src/{specdrum,audio,keyboard,spi}.v`, `usd_bulb.v`, `beta_disk.v`, `nemo_ide.v`,
`kempston_mouse.v`, `gs_flow.v`, `mem_zx_bulb.v`. Копии в `sources/build/` на 28.08 совпадают с
`sources/` байт-в-байт (проверено `diff` для всех 16 файлов), `sources/build/zx` - симлинк на `cores/zx`.
`ps2.v`, `dprs.v`, `dsg.v`, `divmmc_card.v` модулю `main` не нужны (их инстанцирует топ).

### Плюс-аргументы

| аргумент | умолчание | смысл |
|---|---|---|
| `MACHINE=48\|128\|PENT` | `48` | 48 -> `model=0`; 128 -> `model=1`; PENT -> `model=1, pentagon=1` |
| `PROG=<bin> ORG=<hex>` | - | бинарник в ОЗУ по ORG (раскладка `memory.v`, 7FFD=0) + `JP ORG` в байты 0..2 ПЗУ страниц **0 и 1** (48К стартует в страницу 1 = 48 BASIC, 128К/Пентагон - в страницу 0 = 128-меню) |
| `ROM=<file>` | - | альтернативное ПЗУ: `.hex` -> `$readmemh` со страницы 0; бинарник 16К -> страницы 0 **и** 1, 32К -> 0..1, 64К -> 0..3 |
| `RUNUS=<мкс>` | 45000 | длина прогона после снятия сброса |
| `RESETUS=<мкс>` | 5 | длина сброса (`reset`=0) |
| `PINTV/PINTH` | 239/326 | `pent_int_v/h` |
| `PAPERH/PAPERV` | 2/60 | `paper_h/v` |
| `PENT1024 SNOWOFF ULALATE MEMWAIT WARPNC` | 0/1/0/0/0 | одноимённые входы |
| `NOREGINIT=1` | 0 | не обнулять регистровый файл T80 (см. гочи) |
| `PCTRACE=<N> TRACEFROM=<мкс>` | 0/0 | печатать адрес первых N выборок команд, начиная с момента TRACEFROM |
| `ACKMON=1` | 0 | печатать циклы подтверждения прерывания и байт на шине в их `nc3M5` (вектор IM2) |
| `BUSMON=<hex> BUSMON2=<hex>` | выкл | печатать каждый цикл чтения/записи в окне 64 байта от адреса |
| `BUSALL=1` | 0 | печатать ВСЕ циклы шины начиная с TRACEFROM |
| `DUMP=<hex>` | - | в конце напечатать 32 байта с адреса Z80 |
| `CHECKMARK=1` | 0 | проверки маркера/бордюра/счётчика прерываний для `marker.asm` |
| `QUIET=1` | 0 | не печатать таблицу кадров |

### Что взято за умолчания входов от ARM (и откуда)

Все входы, которых нет в таблице выше, - константы: `ram_nobit=0, zc_en=0, zc_turbo=0, mapper=0,
dm_opt=0, dm_pagein_off=0, trdos_en=0, service_en=0, dos_svc_en=0, svc_nmi_en=0, gs_en=0, gs_ctl=0,
gs_ctl_we=0, gs_wq_full/afull/drain=0, fdc_ctl/data=0 (we=0), bdi_always=0, saa_mode=0 (AUTO), nemo_en=0,
km_en=0, joy1/joy2=0, strb/make/code=0 (клавиатура молчит), dirset=0 после инициализации, dir=0,
force_7ffd=0, force_border=0, ear=0, miso=1, nmi=1` (у `cpu.v` это `NMI_n`, 1 = неактивен), `fdc_aclk` -
отдельный такт 100 МГц (домен ARM моста дисковода), `mem_wait=0` (модель DDR в стенде без задержки).

`reset` у `main` активен **нулём** (`cpu.v: .RESET_n(reset)`, `memory.v: if(!reset)`) - как `sp_reset_n` топа.

Ручки Пентагона. В RTL умолчания топа (`bulbulator_zx_ddr_top.v`: `pint 32'h00EF0146`, `paper 64/24`)
дают `pent_int_v=239, pent_int_h=326, paper_h=64, paper_v=24`. В прошивке `arm/loader_main.c:1799-1811`
зашиты `opt_pintv=299`, `opt_pinth=326`, `opt_paper_h=2` (это и есть Pan X, выставлен владельцем 12.08
вместе с INT H=326), `opt_paper_v=60`; ini их может перекрыть. **Стенд берёт 239/326/2/60**: INT V - по
заданию шага (эталон video.v: 239), INT H и Pan X/Y - по прошивке. На длины кадра и строки ни одна из
ручек не влияет (проверено прогоном `MACHINE=PENT PINTV=299 RUNUS=45000`, лог
`logs/run_MACHINE=PENT_PINTV=299_RUNUS=45000.log`: кадр те же 1 146 880 / 143 360 / 71 680 / 320 строк,
меняется только положение спада /INT - `vCount=299`, 134 276 px = 299 × 448 + 324). `pent1024`: топ подаёт туда `pentagon` («Пентагон = 1024»), стенд по заданию
держит 0; включается `PENT1024=1`. `snow_off=1` (в прошивке снег по умолчанию включён, `opt_snow=1`,
но чистая выборка удобнее для измерений; `SNOWOFF=0` возвращает снег).

## Фазы такта (воспроизведено из `clock_zx.v`, ветка `warp_l == 0`)

Мастер 56.6667 МГц (100 × 34/3/20; период 17647.06 пс, в стенде полупериод 8823.5294 пс при
`timescale 1ps/1fs`). Счётчик `ce[3:0]` и все разрешения защёлкиваются по **negedge** мастера, поэтому
DUT видит их устоявшимися на posedge. Один такт Z80 = 16 тактов мастера = 2 пикселя 7 МГц:

| `ce` (старое значение на negedge) | импульсы, видимые на следующем posedge |
|---|---|
| 0 | `ne7M0` + `ne3M5` (граница T-состояния; T80pa защёлкивает DI, `nc3M5`) |
| 4 | `pe7M0` (защёлка бордюра/порта #FE в `main.v`, `vmmCe`, клавиатура) |
| 8 | `ne7M0` + `pe3M5` (шаг автомата T80: `CEN = CEN_p & ~CEN_pol`, `pc3M5`) |
| 12 | `pe7M0` |

`ne14M` = `ce[1:0]==0`. Видео (`video.v`) тактируется `ce = ne7M0`; бордюр защёлкивается на `pe7M0`;
`pc3M5 = pe3M5 & contend & ~cpu_hold`, `nc3M5 = ne3M5 & contend & ~cpu_hold` (`main.v:165-166`) - контеншен
и такты ожидания гасят ОБА разрешения процессора. Прерывание Type 1: `irq <= vduI` на `pc3M5`, `cpu_irq = irq`.

Единицы измерения стенда: **такт мастера** = posedge `clock`; **пиксель** = импульс `ne7M0`; **T без
контеншена** = импульс `pe3M5`; **T процессора** = импульс `dut.pc3M5` (то, на что реально шагает T80).

## Сигналы для стендов-наследников

Счётчики (integer, читать в любой момент): `n_mclk, n_px, n_pe, n_pc, n_m1, n_rd, n_wr, n_iord, n_iowr,
n_irq_raw` (спады `dut.Video.irq`), `n_irq_cpu` (спады `dut.cpu_irq`), `n_intack` (циклы `!m1 && !iorq`),
`n_lines, n_frames, n_x_pc3, n_x_d_m1`. События `ev_line`, `ev_frame`; задачи `wait_frames(n)`, `wait_lines(n)`,
`wait_us(real)`; функции `ram_index(addr)` (индекс в `mem.ram` по адресу Z80 с ТЕКУЩИМ 7FFD), `peek(addr)`.
Последние измеренные длины: `last_line_{mclk,px,pe,pc}`, `last_frame_{mclk,px,pe,pc,lines}`; положение
спада /INT: `irq_px_in_frame, irq_hc, irq_vc, irq_period_mclk, irq_period_pe`.

**Начало строки** = posedge с `ne7M0 && dut.Video.hc == 0` (старое значение `hc`, живёт ровно один
период `ce`; `hCount = hc+1` - «следующее» значение). **Начало кадра** = то же при `dut.Video.vc == 0`.

Иерархические имена машины: `dut.pc3M5, dut.nc3M5, dut.pe3M5` (порт), `dut.contend, dut.cpuck,
dut.mreqt23iorqtw3, dut.cpu_irq, dut.vduI, dut.vduC, dut.a, dut.d, dut.q, dut.mreq, dut.iorq, dut.rd,
dut.wr, dut.m1, dut.rfsh, dut.border` (и порт `border_o`), `dut.Video.{hc,hCount,vc,vCount,fc,fCount,
dataEnable,videoEnable,irq,cn,a,q,hUla,vUla}`, `dut.Memory.{port7FFD,romPage,ramPage,trdos}`, выходы
`r,g,b,i,blank,hsync,vsync`, регистры T80 - `reg_out[211:0]` (раскладка T80pa: `[15:0]=AF, [31:16]=AF',
[39:32]=I, [47:40]=R, [63:48]=SP, [79:64]=PC, [95:80]=BC, [111:96]=DE, [127:112]=HL, [143:128]=IX,
[159:144]=BC', [175:160]=DE', [191:176]=HL', [207:192]=IY, [209:208]=IM, [210]=IFF1, [211]=IFF2`).
Память: `mem.rom[0:65535]` (страница = индекс/16384), `mem.ram[0:131071]` (`{банк[2:0], смещение[13:0]}`),
`mem.scr` (зеркало экрана), `ddr[0:1048575]` (модель PS DDR: банки 8..63 Пентагона, ОЗУ DivMMC).

Внутрь VHDL (T80) из стенда **читать** можно, **писать - нельзя** (см. гочи).

## Результаты приёмки (логи в `logs/`, 28.08.2026)

### Длины кадра и строки

Метод: от начала кадра (posedge `clock` с `ne7M0 && hc==0 && vc==0`) до следующего такого же; строка -
между соседними `ne7M0 && hc==0`. Кадры 2..5 после сброса (кадр 1 частичный - в него попадает сброс).
Процессор в этих кадрах стоит в `HALT` в **неконтендящемся** ОЗУ (0x803A, банк 2), поэтому `pc3M5 == pe3M5`.

| машина | кадр, тактов мастера | кадр, px (`ne7M0`) | кадр, T (`pe3M5`) | кадр, T (`pc3M5`) | строк | строка: мастер / px / T | ожидание |
|---|---|---|---|---|---|---|---|
| 48K (`model=0`) | 1 118 208 | 139 776 | **69 888** | 69 888 | 312 | 3584 / 448 / 224 | 69 888 = 224 × 312 ✓ |
| 128K (`model=1`) | 1 134 528 | 141 816 | **70 908** | 70 908 | 311 | 3648 / 456 / 228 | 70 908 = 228 × 311 ✓ |
| Пентагон | 1 146 880 | 143 360 | **71 680** | 71 680 | 320 | 3584 / 448 / 224 | 71 680 = 224 × 320 ✓ |

Числа одинаковы во всех измеренных кадрах (2..5) и для обоих значений `PINTV` (239 и 299 - не влияет).
Период спадов `Video.irq` (сырой /INT ULA) совпадает с длиной кадра: 1 118 208 / 1 134 528 / 1 146 880
тактов мастера = 69 888 / 70 908 / 71 680 `pe3M5`.

Положение спада `Video.irq` (в пикселях `ne7M0` от начала кадра по определению выше; `hCount/vCount` -
значения в момент спада):

| машина | px от начала кадра | `hCount` | `vCount` | разложение |
|---|---|---|---|---|
| 48K | 111 104 | 2 | 248 | 248 × 448 + 0 |
| 128K | 113 092 | 6 | 248 | 248 × 456 + 4 |
| Пентагон | 107 396 | 326 | 239 | 239 × 448 + 324 |
| Пентагон, `PINTV=299` (прошивка) | 134 276 | 326 | 299 | 299 × 448 + 324 |

То есть спад приходится на пиксель `irqBeg - 2` строки `irqLine` в системе отсчёта стенда (сдвиг 2 -
разница между «старым» `hc` в начале строки и «следующим» `hCount`, в котором `video.v` сравнивает
`irqBeg`). Это измерение положения, не оценка правильности.

### Тот же `HALT` в контендящемся ОЗУ (48K, программа по 0x5000, банк 5)

| кадр | `pe3M5` | `pc3M5` | потеряно T |
|---|---|---|---|
| 2..5 (стабильно) | 69 888 | 57 600 | 12 288 = 192 строки × 64 T |

Измерено, не выведено: при бесконечном `HALT` (M1 каждые 4 T) в 0x4000-0x7FFF процессор теряет ровно
64 T на каждую из 192 строк бумаги. Разбор узора контеншена - задача следующих стендов.

### Проверка (1): программа через `+PROG` (`prog/marker.asm`, 100 мс)

Программа: `DI`, бордюр 2, маркер 0x4000..0x40FF (байт = индекс XOR 0xA5), таблица IM2 0x6000..0x6100 =
0x61, обработчик по 0x6161 инкрементирует слово (0x7000), `EI`, `HALT` в цикле. Стенд читает маркер и
счётчик обратно из своей памяти.

| прогон | маркер | бордюр | спадов `Video.irq` | подтверждений INT | счётчик в ОЗУ (0x7000) | вердикт |
|---|---|---|---|---|---|---|
| 48K, ORG=8000 | 0 расхождений | 2 | 5 | 5 | 5 | PASS |
| 128K, ORG=8000 | 0 расхождений | 2 | 5 | 5 | 5 | PASS |
| Пентагон, ORG=8000 | 0 расхождений | 2 | 5 | 5 | 5 | PASS |
| 48K, ORG=5000 (контеншен) | 0 расхождений | 2 | 5 | 5 | 5 | PASS |

5 прерываний за 100 мс после сброса: первое на строке 248 первого кадра (48K: 55 553 `pe3M5` от СТАРТА
симуляции, растр стартует с `hc=vc=0` в момент 0: 248 × 224 + 1; Пентагон - на строке 239: 53 699 =
239 × 224 + 163, INT H = 326 / 2 = 163 T),
дальше раз в кадр (~20 мс): 15.9 + 4 × 20 = 95.9 мс < 100 мс. Байт вектора IM2 на шине в момент
подтверждения (`ACKMON`): `0xBF`. Адрес на шине в этом цикле = PC команды `HALT` (0x803A): `a[0]=0`,
поэтому мультиплексор `main.v` отдаёт порт #FE `{1, ear|speaker, 1, keyQ}` = 0xBF (не джойстик: `a[5]=1`,
и не плавающая шина). Таблица однородна, поэтому вектор всегда 0x6161.

### Проверка (2): см. таблицу длин выше. Проверка (3): настоящее ПЗУ, 5 мс

| машина | первые выборки (M1) | за 5 мс: M1 / чтений / записей | PC в конце | что это |
|---|---|---|---|---|
| 48K | 0000 0001 0002 0005 11CB 11CC 11CE ... 11DC 11DE 11DF 11E0 (цикл) | 2219 / 3327 / 551 | 0x11DE, HL уменьшается FF93 → FE47 | старт 48 BASIC (`DI; XOR A; LD DE,FFFF; JP 11CB`), тест ОЗУ `11DC..11E0` |
| 128K | 0000 0001 0004 0005 0006 0007 0004 ... | 2725 / 3407 / 0 | 0x0005..0x0009 | старт 128-меню: `DI; LD BC,692B; DEC BC; LD A,B; OR C; JR NZ` - задержка 26 923 × 26 T ≈ 700 000 T ≈ 200 мс |

## Гочи (оплачены при постановке стенда)

1. **`xvlog` только с `--relax`.** `wd1793.sv` использует `q`, `A_DATA`, `edsk_*` до объявления
   (`VRFC 10-3380`), а `main.v` объявляет `svc_nmi` (строка 625), `nemo_dev_slave`, `nemo_drq_live`
   (864-865) ПОСЛЕ первого использования в списках портов (483, 857, 859) - `VRFC 10-2938 already
   implicitly declared`. Синтез Vivado это ест молча, xvlog без `--relax` отказывается.
2. **`wd1793.sv` не элаборируется как есть:** `reg scan_active` объявлен у строки 1055, а используется
   с 104 и ВНУТРИ `generate if(RWMODE)` (129) - xelab: `Unresolved Hier Name: \genblk1.scan_active`.
   `run.sh` при каждой сборке генерирует `gen/wd1793_xsim.sv` из живого исходника с одним изменением
   (объявление перенесено к строке 100) и падает, если якоря не найдены ровно по одному разу.
   Это подтверждение записи из `HANDOVER_CURRENT.md` («forward declarations... xvlog отвергает»).
3. **`xelab --timescale 1ps/1fs` обязателен:** у исходников машины нет `` `timescale ``, у стенда есть.
4. **Писать в регистры T80 из Verilog нельзя:** иерархическое присваивание
   `dut.Cpu.Cpu.u0.Regs.RegsH[k] = 0` (приём стенда ep4spectrum) валит xelab 2023.1 с `SIGSEGV`.
   Вместо этого стенд во время сброса на 1 мкс поднимает `dirset` при `dir = 0` - штатный порт
   инжекции регистров: `T80_Reg` грузит `DIR` по любому такту без гейта сброса, `ACC/F/PC/SP/I/R`
   сбрасывает `RESET_n`. Без этого BC/DE/HL/IX/IY = `x` и `x` расползается со стека.
5. **Регистры без сброса = `x` навсегда.** Инициализируются в момент 0 из стенда: `video.v`
   `hc, hCount, vc, vCount, fc, fCount, dataEnable, videoEnable, dataInput, attrInput, dataOutput,
   attrOutput, a, q`; `main.v` `mreqt23iorqtw3, cpuck, mic, speaker, border`; `memory.v`
   `mapOnIORQData`; `specdrum.q`. ОЗУ модели (`ram`, `scr`, `ddr`) обнуляются (в железе там мусор,
   но не `x`). После этого `n_x_pc3 = 0` и `n_x_d_m1 = 0` во всех прогонах.
6. **Параллельные прогоны требуют СВОЕЙ копии `xsim.dir`.** xsim пишет команду запуска (с
   плюс-аргументами!) в `xsim.dir/tb_zx/xsim_script.tcl` и потом её исполняет; семь прогонов на
   общем снапшоте подменили друг другу аргументы (логи оказались перепутаны). `--wd=<имя>`
   копирует снапшот (12 МБ).
7. **Тестовая программа обязана быть собрана под свой ORG.** Бинарник для `org 8000h`, загруженный по
   0x5000, дал картину «в контендящемся ОЗУ LDIR копирует нули, прерывание уходит в пустоту» -
   выглядело как дефект контеншена, а было `ld hl,isr` с абсолютным адресом 0x803C (там нули).
   Найдено монитором шины (`BUSALL`): `RD A=5023 D=80`. У Z80 нет способа узнать PC без абсолютных
   адресов (`CALL` тоже абсолютный), поэтому `prog/build.sh` собирает отдельный бинарник на каждый ORG.
8. **Короткий прогон ПЗУ 128K/Пентагона показывает только стартовую задержку** (0x0004..0x0007,
   ≈ 200 мс); это свойство ПЗУ, не стенда.
9. `WARNING: Insufficient data from the input file for $fread` при `PROG`/`ROM` - безвредно (буфер 64К
   больше файла).
10. Таблица кадров печатается со второго начала кадра; строка «последний кадр: мастер 9 ...» в
    прогонах короче одного кадра - артефакт первого частичного кадра, не измерение.

## Что не измерено

- Правильность ПОЛОЖЕНИЯ /INT и узора контеншена относительно эталонов (14335/14336 и т. п.) - здесь
  только зафиксированы координаты и потери T; это предмет следующих стендов.
- Работа дисковода, DivMMC, GS, NEMO, мыши в стенде не проверялась (все выключены константами);
  `wd1793` присутствует в элаборации через `gen/`, но не стимулируется.
- Модель DDR - нулевая задержка, `mem_wait` не поднимается; тайминги расширенных банков Пентагона
  этим стендом не воспроизводятся.
- Снег выключен по умолчанию (`SNOWOFF=1`); в прошивке он включён.
