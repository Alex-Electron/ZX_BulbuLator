# Эталонные числа ep4spectrum (Сергей Потапов), снятые тем же прибором — xsim

Дата прогона: 2026-08-28. Инструмент: Xilinx xsim 2023.1 (`xvlog` / `xelab` / `xsim`) на ThinkPad.
Исходники: `/tmp/ep4` (не правились), рабочая копия — `/tmp/ep4sim`. Копия `video.v`
байт-в-байт равна оригиналу (md5 `386c5a3b4851c2efecaffac81211e3f4`), T80 — его Verilog-порт
(`T80.v` ver 306, `T80se.v`, `T80_MCode.v`, `T80_ALU.v`, `T80_Reg.v`).

Единицы, которыми говорит его `video.v` и все его стенды:

| единица | что это | пересчёт |
|---|---|---|
| **count** (счёт) | один шаг `hcounter` = один импульс `CLKEN` (14 МГц) | 1 count ≈ 71.43 нс |
| T-state (T) | такт Z80 3.5 МГц | **1 T = 4 counts** |
| пиксель | 7 МГц | **1 px = 2 counts**, 8-пиксельная группа = 16 counts |
| строка 224 T | 48K / Pentagon | 896 counts (`hcounter` 0..895) |
| строка 228 T | 128K / +2A/+3 | 912 counts (`hcounter` 0..911) |

Тактирование стендов: `CLK` 28 МГц (`always #17.857`), `CLKEN` — каждый второй фронт
(регистр, переключается на каждом `posedge CLK`). Код машины `MACHINE[1:0]` (`video.v:157-160`):
**0 = Sinclair 48K, 1 = Sinclair 128K/+2, 2 = Sinclair +2A/+3, 3 = Pentagon 128K.**

Каталог этого отчёта: `research/15-pentagon/sim/timing/reference/`. Рядом лежат:
`stands/` — адаптированные копии его стендов и два моих (`tb_bsweep.v`, `tb_geo2.v`), `run_tb.sh`;
`logs/` — полные логи каждого прогона; `tests/zxtests3/` — собранные тесты Бобровского.

## 2. `tb_intgeo.v` — где прерывание стоит относительно растра

**Что мерится.** Только модуль `video`, без процессора. После сброса пропускается первое
прерывание, на втором `@(negedge nirq)` включается счётчик `counts` (шаги `CLKEN`, то есть шаги
`hcounter`), выключается на `wait (vid.picture === 1'b1)` — первый подъём `picture = hpicture & vpicture`
(`video.v:233`), то есть **первый бумажный пиксель кадра**. Печатается `counts` и `counts/4`
(целочисленное деление → T-states). Плюс-аргументы: `MACHINE`, `INTADJ` (в count'ах, шаг = 1 count = полпикселя).

**Что влияет:** `int_line_base` (`video.v:1072-1074`), `int_hpos_base` (`1149-1184`), `int_adj_eff`
(`169-170`, у Pentagon принудительно 0), `hline`, момент `hpicture <= 1` (`1436`: `hcounter[9]==0 &&
hcounter[2:1]==2'b11 && hcounter[0]==1`, то есть на счёте 7 → `picture` виден с `hcounter = 8`).

**Напечатано дословно (по машинам):**

| MACHINE | вывод стенда | counts | = T + counts | int_line | int_hpos | hline |
|---|---|---|---|---|---|---|
| 0 (48K) | `INT -> first paper pixel: 57346 counts = 14336 T-states (a 48K wants 14336)` | 57346 | 14336 T + 2 | 248 | 5 | 896 |
| 1 (128K) | `INT -> first paper pixel: 57455 counts = 14363 T-states` | 57455 | 14363 T + 3 | 248 | 8 | 912 |
| 2 (+2A/+3) | `INT -> first paper pixel: 57457 counts = 14364 T-states` | 57457 | 14364 T + 1 | 248 | 6 | 912 |
| 3 (Pentagon) | `INT -> first paper pixel: 71953 counts = 17988 T-states` | 71953 | 17988 T + 1 | 239 | 630 | 896 |

Разбор 48K: `nIRQ` падает на фронте, где `hcounter` становится 6 строки 248 (условие
`hcounter >= int_hpos` = 5 проверено при `hcounter = 5`, регистр обновился на следующем фронте,
`video.v:1554-1559`); `picture` поднимается на `hcounter = 8` строки 0. 64 строки × 896 + 2 = 57346.
То есть **его 48K даёт 14336.5 T от фронта nIRQ до первого пикселя** — на полтакта раньше
«ровных» 14336 (запись `int_hpos_base = 5` вместо 7 намеренная, `video.v:1149-1166, 1168-1181`:
фронт нельзя класть точно на момент выборки процессора, иначе гонка; 7 давало бы 57344 = 14336.00).
128K: 63 строки × 912 − 1 = 57455 (=14363.75 T; 8 count'ов «оставляют гонку, машина не
смотрелась», `video.v:1181-1183`). Pentagon: 81 строка × 896 − 623 = 71953 (int на счёте 630 строки 239).

## 3. `tb_intack.v` — цена приёма прерывания у его T80

**Что мерится.** Только `T80se #(.T2Write(1))`, `CLKEN = 1` (один такт CLK = один T-state),
`WAIT_n = 1`, плоская память 64 КБ. Программа: `DI; LD SP,$C000; LD A,$81; LD I,A; IM 1|IM 2; EI` и
затем либо `HALT`, либо «горка» NOP'ов. Через 200 тактов после сброса `INT_n` опускается (и держится 64
такта); `tcount` считает фронты `CLK` от этого момента до первого фронта, где `IORQ_n=0 && WR_n=0`
(обработчик начинается с `OUT ($FE),A` — момент, когда ULA защёлкнула бы бордюр). Векторная
таблица IM2 — 257 байт `$81` по `$8100` → вектор `$8181`.

**Напечатано дословно:**

```
INT ACCEPTANCE
  IM 1, on a slide: 23 T-states from INT to the border write
  IM 1, halted    : 23 T-states from INT to the border write
  IM 2, on a slide: 29 T-states from INT to the border write
  IM 2, halted    : 29 T-states from INT to the border write

  IM1 halted - IM1 on a slide = 0 (a real Z80: 0, allowing the 4-T grid)
  IM2 halted - IM2 on a slide = 0 (a real Z80: 0, allowing the 4-T grid)
  IM2 - IM1, on a slide       = 6 (a real Z80: 6)
  IM2 - IM1, halted           = 6 (a real Z80: 6)
```

| случай | тактов от спада INT_n до IORQ&WR первой `OUT ($FE),A` |
|---|---|
| IM 1, NOP-горка | 23 |
| IM 1, HALT | 23 |
| IM 2, NOP-горка | 29 |
| IM 2, HALT | 29 |

Число включает саму `OUT (n),A` до её T2 (с `T2Write=1` IORQ/WR у него выставляются в T2, а не в T3).
В комментариях `video.v:1130-1132` он расшифровывает это как «13 T приёма для IM1 и 19 для IM2,
ровно как у Z80, HALT ничего не меняет». Разница 6 воспроизведена; равенство HALT/NOP тоже.
Фаза прихода INT относительно границы команды в этом стенде одна (200 тактов после сброса);
разброс по фазам стенд не печатает.

## 4. `tb_iowin.v` — форма окна контеншена по тактам

**Что мерится.** Модуль `video` без процессора. Сначала — на каких строках вообще бывает
`CONTENTION=1` (печатается диапазон). Потом на строке 100 от `hcounter == 0` каждые 8 фронтов CLK
(= 4 count = 1 T) снимается `CONTENTION` и `CONTENTION_IO`; печатается по символу на T-state строки
(`#` — процессор был бы задержан на этом такте, `.` — свободен), сумма и позиция первого `#`.
Первая выборка сделана при `hcounter = 3`, дальше `hcounter = 3 + 4·t` — то есть символ `t`
отвечает count'ам `3+4t` (T-state `t` строки, если считать T0 = count 0..3).

**Что влияет:** `hc_sum = hcounter + CONT_ADJ·4 − t_counts(4) − cont_lead` (`video.v:376-378`),
`cont_span` (`409`), `CONTENTION = vpicture & ~hc_cont[9] & (hc_cont[4:2] < cont_span)` (`410-411`);
для IO — `hi_sum = hc_sum + io_base + IO_ADJ·4` (`474-476`), `CONTENTION_IO` (`481-482`).

## 5. `tb_border.v` — на сколько пикселей запаздывает цепочка бордюра

**Что мерится.** Модуль `video`, `BORD_PHASE = 9`, `BORD_DELAY = 0` (как на плате:
`ep4spectrum.v:324-325`). Через 4000 тактов CLK после сброса `BORDER_IN` меняется 0→7, счётчик `pix`
считает фронты `CLKEN` с `hcounter[0] == 1` (пиксельные тики — те же, на которых сдвигается цепочка
`border_d1..d3`) до `vid.border_out == 7`. Одна фаза на машину (та, на которой оказались счётчики).

**Напечатано дословно:**
```
MACHINE 0: border_out follows after 5 pixel ticks
MACHINE 3: border_out follows after 4 pixel ticks
MACHINE 1: border_out follows after 5 pixel ticks
```

Число для Sinclair-машин зависит от фазы момента записи внутри 16-count'овой группы (см. мой
`tb_bsweep` ниже), для Pentagon — нет.

## 6. `tb_qflag.v` — флаги XF/YF после SCF (тип процессора)

Не про тайминги, но входит в набор. `T80se` без ULA; два случая через `POP AF` + `SCF` + `PUSH AF`,
результат уходит в `OUT ($01)` / `OUT ($02)`. Напечатано:
```
  case A  F=$28 A=$00 then SCF : got $29
  case B  F=$00 A=$28 then SCF : got $29
  Zilog wants $29 in both. Bits from A alone give $01 and $29.
  ZILOG - both bits come from (Q ^ F) | A
```
То есть его T80 (ver 306) ведёт себя как Zilog: XF/YF = (Q ^ F) | A.

## 7. Мои дополнительные стенды на его `video.v` (те же единицы, то же тактирование)

### 7.1 `tb_bsweep.v` — задержка бордюра по всем 16 фазам группы

`BORDER_IN` меняется сразу после фронта `CLKEN`, на котором `hcounter` стал `192+P` (P = 0..15, каждая
фаза на своей строке 100+P, внутри видимой части строки). Считаются count'ы (шаги `hcounter`) и
пиксельные тики до `border_out == новое`. `BORD_PHASE = 9`.

| фаза = `hcounter[3:0]` при записи | 48K/128K/+3, `BORD_DELAY=0` (плата): counts / px | 48K, `BORD_DELAY=3`: counts / px | Pentagon (латч каждый пиксель + 3 стадии): counts / px |
|---|---|---|---|
| 0 | 10 / 5 | 16 / 8 | 8 / 4 |
| 1 | 9 / 5 | 15 / 8 | 7 / 4 |
| 2 | 8 / 4 | 14 / 7 | 8 / 4 |
| 3 | 7 / 4 | 13 / 7 | 7 / 4 |
| 4 | 6 / 3 | 12 / 6 | 8 / 4 |
| 5 | 5 / 3 | 11 / 6 | 7 / 4 |
| 6 | 4 / 2 | 10 / 5 | 8 / 4 |
| 7 | 3 / 2 | 9 / 5 | 7 / 4 |
| 8 | 2 / 1 | 8 / 4 | 8 / 4 |
| 9 | 1 / 1 | 7 / 4 | 7 / 4 |
| 10 | 16 / 8 | 22 / 11 | 8 / 4 |
| 11 | 15 / 8 | 21 / 11 | 7 / 4 |
| 12 | 14 / 7 | 20 / 10 | 8 / 4 |
| 13 | 13 / 7 | 19 / 10 | 7 / 4 |
| 14 | 12 / 6 | 18 / 9 | 8 / 4 |
| 15 | 11 / 6 | 17 / 9 | 7 / 4 |
| **диапазон** | **1..16 counts = 1..8 px** | 7..22 counts = 4..11 px | **7..8 counts = ровно 4 px** |

Закон для Sinclair-машин: задержка = ((9 − фаза) mod 16) + 1 count, то есть значение защёлкивается
на ближайшем фронте с `hcounter[3:0] == 9`, дальше при `BORD_DELAY=0` идёт на выход без стадий.
Каждая стадия `BORD_DELAY` добавляет 2 count = 1 px. У Pentagon латч на каждом пиксельном тике и
3 стадии принудительно (`bord_delay_eff`, `video.v:630-631`) → всегда 4 px.
128K и +2A/+3 дали ту же таблицу, что 48K (логи `logs/bsweep_MACHINE1_BDELAY0.log`, `..._MACHINE2_...`).

### 7.2 `tb_geo2.v` — геометрия растра в count'ах, считанная с сигналов

Состояние снимается на `negedge CLK` после разрешённого фронта (регистры уже обновились;

| ширина `nIRQ=0`, counts | 128 (32 T) | 144 (36 T) | 144 (36 T) | 128 (32 T) |

| первый `picture=1` при (строка, hcounter) | 0, 8 | 0, 8 | 0, 8 | 0, 8 |
| спад `nIRQ` → `picture`, counts | 57346 = 14336 T + 2 | 57455 = 14363 T + 3 | 57457 = 14364 T + 1 | 71953 = 17988 T + 1 |
| спад `nIRQ` → первый `CONTENTION=1`, counts | 57346 (стр. 0, hc 8) | 57455 (стр. 0, hc 8) | 57461 (стр. 0, hc 12) | 71949 (стр. 0, hc 4) |
| строки с `picture` | 0..191 | 0..191 | 0..191 | 0..191 |
| строка 100: `picture` on / off, hcounter | 8 / 520 | 8 / 520 | 8 / 520 | 8 / 520 |
| строка 100: `CONTENTION` первый / последний hcounter | 8 / 511 | 8 / 511 | 12 / 519 | 4 / 507 |

| строка 100: `PORT_FF_ACTIVE` первый hcounter | 0 | 0 | 0 | 0 |

Про «контеншен на такт раньше первого пикселя (14335)»: на **сигнале** `CONTENTION` у 48K это не
видно — он поднимается на том же count'е 8, что и `picture`. Оба сдвига в `hc_sum` (`video.v:376-378`)
уравновешены: `t_counts = 4` (структурный: T80se показывает MREQ/IORQ только в T2, поэтому окно
отодвинуто на такт назад, чтобы задержка считалась от T1 цикла, `video.v:308-322`) и `cont_lead = 4`
(само «14335», `video.v:325-343`). Без `cont_lead` окно стояло бы на count 12, то есть на такт позже
пикселя; с ним — вровень с пикселем на сигнале, что для процессора означает «на такт раньше».
У Pentagon `cont_lead = 0` → сигнал на count 4 (но в `ep4spectrum.v:1299` он для Pentagon отключён);
у +2A/+3 `cont_lead = 8` → count 12.

### 8.1 Тактирование процессора и видео на плате (`clocks.v`)

Счётчик `counter[3:0]` идёт на **negedge** 28 МГц. `CLKEN_VID = counter[0]==1` (каждый второй такт =
14 МГц), `CLKEN_CPU` при SPEED=0: `counter[2:0]==6` — один раз в 8 тактов = 3.5 МГц (то есть один
T-state = 2 шага `hcounter`... нет: `hcounter` шагает на `CLKEN_VID`, 4 раза за T-state, как и написано
у него всюду). `CLKEN_PSG = counter==8` (1.75 МГц). Процессор получает `cpu_clken_gated = cpu_clken &
~contention` (`ep4spectrum.v:1308`) — **удержание через разрешение, не через WAIT_n**.

### 8.2 Как считается контеншен на стороне процессора (`ep4spectrum.v`)

- `T80se #(.T2Write(1))` (:996): у записи `WR_n`/`MREQ_n` на том же фронте, что у чтения (конец T1),
  а не на такт позже; измерение до правки: чтения задерживались как 5,4,3,2,1,0,0,6 (на такт позже
  эталона), записи 4,3,2,1,0,0,6,5 (на два), :987-990.
- Адрес под контеншеном: `cont_addr = a[14] & (~a[15] | cont_page)` (:1059); `cont_page` = бит 0 номера
  страницы у 128K (нечётные банки), бит 2 у +2A/+3 (банки 4..7) (:1058).
- Момент оплаты памяти — **T1 каждого машинного цикла** по выведенному из T80 `TS`: `cycle_first =
  (cpu_ts == 1)` (:1158), плюс при `cont_model=1` каждый «лишний» T-state цикла (`cpu_ts > 4` для M1,
  `> 3` для остальных, :1177-1181) — это внутренние такты вида `hl:1`, которые ULA 48K тоже берёт.
  Для +2A/+3 вместо этого — по `~MREQ_n` с флагом `mreq_paid` (:1182, 1193-1200).
- `cont_mem = ~io_cyc & cont_trigger & cont_addr` (:1271); удержание длится, пока `CONTENTION` (окно
  из `video.v`) в фазе задержки — один раз за цикл.
- IO: ключ — микрокодовый `IO_CYC` (истинен с T1), не `IORQ_n` (:1092). Шаг за шагом `io_seq` 1..3
  (:1215-1240), точки проверки по таблице FUSE (:1264-1266): страница под контеншеном и A0=0 → T1,T2
  (C:1,C:3); под контеншеном и A0=1 → T1..T4 (C:1×4); обычная страница и A0=0 → только T2 (N:1,C:3 —
  случай `OUT (#FE)`); обычная и A0=1 → ничего (N:4). `cont_io = (io_start | io_seq != 0) & io_point` (:1273).
- Итог: `contention = (machine != PENT) & (vid_contention & cont_mem | vid_contention_io & cont_io)`
  при `cont_mode=2` (:1299-1304). Одно окно `video.v` на память и IO, IO — своей копией со сдвигом `io_base`.
- `nIRQ` подаётся в ядро **напрямую**, без пересинхронизации (`assign cpu_irq_n = vid_irq_n`, :1047):
  T80 сам защёлкивает `INT_s <= ~INT_n` на CEN, вторая защёлка стоила такт (:1021-1046).
- Порт ULA: `ula_enable = ~ioreq_n & m1_n & ~a[0]` (:1699), `ula_port.v` защёлкивает `BORDER_OUT`
  на **каждом** такте 28 МГц при `ENABLE & ~nWR`, без разрешений (:1395-1409) — момент = первый такт
  28 МГц, где IORQ и WR оба низкие (T2 при `T2Write=1`).

### 8.3 Путь бордюра и бумаги в `video.v` (пикселями)

`BORDER_IN` → `border_latched` по `border_update` (Sinclair: раз в 8 px на фазе `BORD_PHASE=9`;
Pentagon: каждый px; :532-535, 640-644) → `border_d1 → d2 → d3` по пиксельным тикам (:645-648) →
`border_out` = тап по `bord_delay_eff` (Sinclair на плате — 0 стадий, Pentagon — 3; :630-636) →
`red/green/blue` комбинационно (:905-931) → регистры `R/G/B` на 28 МГц (:936-947).
Бумага (`picture`, `dot`, `attr`) на Sinclair проходит **9** пиксельных стадий (`picture_d[8]`,
:723-747), на Pentagon — 0. Смысл, по его же комментарию :691-722: 1 px — перекос между двумя путями
вывода, 8 px — целая группа, которую фазой сетки не взять (фаза двигает сетку, программы с разными
остатками отвечают на неё по-разному). Цена — вся картинка стоит на 9 px правее в кадре, что
компенсируется `sync_off` (4 px) на синхроимпульсах.

## 10. `testapp/zxtests3` — тесты Яна Бобровского (zxtests v3, лицензия GPL)

| программа | что измеряет |
|---|---|
| `btime` (border time) | на каком такте от INT (клавиши Q/A ±1) машинный цикл `OUT (#FE)` попадает на смену бордюра; старт 14336−224 |
| `stime` (screen time) | такт цикла ЗАПИСИ в экран относительно растра; старт 14335 |

  `altpll`/`altsyncram` — его числа про латч порта относительно задержки контеншена **не сняты**.
