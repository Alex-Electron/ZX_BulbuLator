# Веб-КВМ на ARM: конструкция ВОССТАНОВЛЕНА из собранного бинарника

**Дата:** 2026-08-05. **Повод:** владелец захотел тестировать TR-DOS удалённо и попросил веб-сервер
на самом ARM, а не мой JTAG.

## Что случилось с прежней работой

Веб-КВМ **уже был написан и работал** (владелец помнит стриминг экрана с высоким FPS). Исходники жили
в ВМ, которая умерла: в `~/sdboot/ws/net_kvm/src/` файлы на месте, но **все нулевого размера**

Уцелел собранный `net_kvm.elf` (1.38 МБ) и прошитый `flash/net_kvm.bin` (229 КБ).

**Из ELF конструкция восстановлена почти целиком** — весь веб-интерфейс лежал в нём строками.

## Восстановленный API

```
GET  /frame        сырой кадр из DDR, БЕЗ сжатия
GET  /info         JSON описания кадра и машины
POST /api/key      {code, release}      клавиатура в машину
POST /api/joy      {mask}               джойстик
POST /api/fs       {...}                файловые операции
POST /api/launch   {dir, name}          запуск файла
POST /api/machine  {id}                 смена машины
GET  /api/opt      / POST               опции
GET  /api/net      / POST {mode,ip,mask,gw}   DHCP или статика, горячая перезагрузка
```

Ответы сервера: `HTTP/1.1 200 OK`, `Cache-Control: no-store`, `Connection: keep-alive`.

`/info` отдаёт:

```json
{"fb_addr":"0x%08x","fb_size":%u,"w":%u,"h":%u,"bpp":%u,"hz":%u,
 "pack":"16pix/u64","nib":"{i,r,g,b}","palette":"hdmi-rgbi",
 "version":"0x%08x","machine_id":"0x%08x","family":"%s"}
```

## Ключевое решение, объясняющее высокий FPS

**ARM не кодирует картинку вообще.** `/frame` отдаёт сырой кадр (для ZX это 57984 байта, 384×302,
4bpp), а разворачивание в пиксели делает БРАУЗЕР:

```js
let W=384,H=302,FB_SIZE=57984,targetHz=50,family='zx';
let img=ctx.createImageData(W,H), pix32=new Uint32Array(img.data.buffer);
for(let i=0;i<need;i++){ const b=u8[i];
  pix32[o++]=PAL32[b&15]; pix32[o++]=PAL32[(b>>4)&15]; }   // байт = ДВА пикселя
ctx.putImageData(img,0,0);
```

Плюс двойная предзагрузка кадров (`nextFetch`) и счётчик FPS. Интерфейс сам подстраивается под
машину по `/info` (`resizeFb`), поэтому ZX 384×302 4bpp и NES 256×240 8bpp работают одним кодом.

## Что это значит для реализации заново

**Хорошие новости, все три проверены:**

1. **Ethernet не требует ПЛИС.** В DTS от u-boot-порта: `&gem0 { phy-mode = "rgmii-id";
   ethernet-phy@0 { reg = <0x0>; } }` и **никакого `pinctrl`-переопределения** - значит штатные MIO,
   а не PL. RGMII-мост в битстриме не нужен, LUT не тратится (при 87.3 % это принципиально).
   Этим закрыт открытый вопрос из заметок «MIO-MII или PL-RGMII».
2. **lwIP 2.1.3 уже вендорен и собран** для второго ядра:
   `~/sdboot/ws/ebaz/ps7_cortexa9_1/.../libsrc/lwip213_v1_0/src/lwip-2.1.3/`. Самая тяжёлая
   зависимость на месте.
3. **Фронтенд восстановлен** - переписывать интерфейс не нужно, он есть в строках.

**Что писать заново (на C):** инициализация lwIP + DHCP, цикл HTTP-сервера с маршрутизацией,
обработчики API. Кода немного: `/frame` это memcpy 57 КБ, `/info` это snprintf, остальное - POST'ы.

**Архитектура, которая напрашивается:** сервер живёт на **core1** (там и BSP с lwIP), а функции
навигатора вызывать не надо - для них уже есть **мейлбокс на `0x0F700000`**, которым core0 обслуживает
файловые операции, запуск, инжект клавиш (cmd 11) и перезагрузку ядра. То есть core1 переводит REST в
мейлбокс, а вся логика остаётся в одной прошивке. Это же снимает опасение владельца «придётся
реализовать все функции навигатора в вебквм»: их не переписывали и не надо - их вынесли в API.

## Порядок работ

1. Поднять gem0 на MIO + DHCP на core1, проверить `ping` (без сервера).
2. HTTP-сервер + `/info` + `/frame` - уже даёт удалённый просмотр экрана.
3. `/api/key` через мейлбокс cmd 11 - и появляется удалённое управление, то есть тест TR-DOS
   становится возможен без присутствия у платы.
4. Остальные API (`fs`, `launch`, `machine`, `opt`, `net`) - по одному.
5. Фронтенд взять из `RECOVERED_UI_FRAGMENTS.txt`.

⚠ **Урок, который стоило потерять один раз:** единственным носителем этой работы был бинарник в
неверсионируемой папке рабочей области. Всё, что дошло до платы, обязано лежать в репозитории.
