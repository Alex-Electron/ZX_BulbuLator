![ZX-BulboNavigator: файловый менеджер с полноцветным интерфейсом в стиле DOS Navigator, работающий на управляющей плоскости ARM поверх живого экрана Spectrum](images/navigator-step14.jpg)

*ZX-BulboNavigator поверх работающего ядра ZX Spectrum 128K. Полноцветное текстовое OSD размером 80×25, полностью отрисовываемое простаивающим ядром ARM, содержит файловый менеджер в стиле DOS Navigator, универсальную кассетную станцию и музыкальный плеер. За наложением видно собственное меню Spectrum 128 — ядро продолжает работать; OSD его не останавливает.*

Это дерево продолжает инфраструктуру шага 14 (цветной DDR-OSD + BulboNavigator) и реализует **Шаг 15**: первая «другая машина» (Pentagon 128 как timing leg на ядре Atlas 128K) с корректным растром 320 строк, широким бордюром, floating bus = 0xFF, без contention, живыми тюнерами INT и paper-offset для идеального позиционирования бордюра и логотипа, а также машино-агностичной управляющей плоскостью.

Вся новая разработка по мульти-машинности (начиная с Пентагона) ведётся здесь. Дерево 14-color-osd заморожено как опубликованный снапшот шага 14.

Всё это работает на Cortex-A9, который в остальное время простаивает. Ядро Spectrum продолжает крутиться под ним; OSD — это наложение, а не остановка машины. И, как на каждом шаге, дизайн не зависит от конкретной машины: браузер, кассетная станция и плеер ничего не знают про ZX. Они взаимодействуют через стабильный контракт AXI, так что та же самая среда без изменений будет работать и на будущем ядре NES или C64.

## OSD-холст с полным цветом

Старая панель с разрешением 1 бит на пиксель заменена на **ARGB8888-холст размером 640×400 пикселей, организованный в виде ячеек размером 80×25 символов** с VGA-шрифтом 8×16. Используется шрифт CP866 (Terminus, OFL): ASCII, полный набор символов для рисования окон в DOS и кириллица, так что навигатор может рисовать аутентичные двухстрочные рамки и русский текст.

- Холст находится в **окне DDR, выровненном по 1 МБ и не подлежащем кэшированию** по адресу `0x0F800000` (внутри области `NC_BASE`, зарезервированной файлом `lscript.ld`). Поскольку окно при запуске помечено как некешируемое, записи ARM согласуются с фабрикой без очистки кэша для каждого кадра.
- Новый считыватель фабрики, **`osd_ddr_rd`**, передаёт данные с холста по **AXI-HP1** и отдаёт пиксели **`osd_compositor`**, который выполняет альфа-смешивание пикселей с потоком HDMI в реальном времени. Тени окон полупрозрачные (альфа `0x80`), тела диалоговых окон — непрозрачные, а яркость/прозрачность и положение всего слоя можно настроить в меню «Options».
- **`OSD_CTRL`, бит 1** включает цветной слой; **F8** переключает его, а **F12** показывает/скрывает навигатор.
- Золотое правило всего OSD: **только инкрементальная перерисовка.** Полная перерисовка экрана вызывает мерцание, поэтому перерисовываются только те строки, которые изменились (`dn_draw_file_row`); полная перерисовка происходит только при закрытии модального диалога.

## Файловый браузер BulboNavigator

Браузер очень похож на DOS Navigator. Колонки: **Имя / Расширение / Размер / Дата**; в заголовке выделяется активное поле сортировки и отображается стрелка направления вверх/вниз. В правой колонке рамки находится полоса прокрутки в стиле Turbo Vision (стрелки + пропорциональный ползунок). Папки можно оформлять с помощью скобок, значка или косой черты в конце, а курсор выделяет любую строку, которая не помещается целиком.

- **Сортировка** (горячие клавиши DOS Navigator): `Ctrl+F3` — по имени, `Ctrl+F4` — по расширению, `Ctrl+F5` — по размеру, `Ctrl+F6` — по дате. Повторное нажатие на то же поле меняет порядок на обратный. В диалоге `Files → Sort` те же поля + флажок «По убыванию».
- **Навигация**: стрелки, `PgUp`/`PgDn`, `Home`/`End` (переход к первой/последней записи), строка `..` перемещает вверх. `Enter` открывает папку или запускает файл в зависимости от расширения — снэпшот `.z80`/`.sna` (загрузчик из шага 12), кассету `.tap`/`.tzx`/`.wav`/`.mp3` или мелодию `.psg`/`.mp3`/`.wav`.
- **Маркировка группы**: клавиша `Insert` помечает запись (желтым) и перемещает курсор вниз. `Пробел` зарезервирован для паузы проигрывателя, поэтому больше не используется для маркировки.
- **Выбор группы по маске** (серые клавиши `+`/`-`/`*` в DOS Navigator, здесь на `Shift`+цифровая клавиатура, чтобы основные клавиши цифровой клавиатуры оставались свободными для регулировки громкости): `Shift+KP +` добавляет теги ко всем элементам, соответствующим маске, `Shift+KP -` снимает теги, `Shift+KP *` инвертирует выделение. Механизм масок представляет собой практичный поднабор DN — `*` и `?`, без учета регистра, списки с запятыми/точками с запятой (`*.tap,*.tzx`), начальный `-` для отрицания (`*.* -*.tmp`), а `*.*` также подходит к именам без расширений.

Клавиши теперь работают надёжно: главный цикл и все диалоговые окна читают данные из одной общей таблицы состояний клавиш, а линия PS/2 имеет сторожевой таймер, который пересинхронизируется при таймауте в середине байта. Старое поведение «неотзывчивые клавиши, для горячей клавиши нужно три попытки» исчезло.

## Работа с файлами и диалог «Копировать/Переместить»

Панель выполняет реальные операции на SD-карте (FatFs, длинные имена файлов до 255 символов, D-cache включён):

- **`F5` Копировать**, **`F6` Переименовать/Переместить** (в стиле Total Commander — поле заранее заполняется полным путём выбранного элемента; измени имя, чтобы переименовать, или папку, чтобы переместить), **`F7` MkDir** (создаёт целую цепочку каталогов), **`F8` / `Delete`** (рекурсивно, с двойным подтверждением для непустой папки).
- Полное **окно диалога «Копировать/Переместить»** в стиле DOS Navigator (78×15) заменяет старый однострочный запрос: поле целевого пути, группа переключателей для разрешения конфликтов с шестью режимами (**Перезаписать / Добавить / Возобновить / Пропустить / Обновить / Спросить**) и флажки опций (проверить свободное место, удалить исходный файл = превратить «Копировать» в «Переместить», проверить запись). Одно линейное кольцо табуляции, `Пробел` устанавливает переключатель или включает/выключает флажок, `Enter` = «ОК», `Esc` = «Отмена». `Спросить» открывает поддиалог для каждого файла.
- И `F5`, и `F6` подают данные в общий механизм разрешения путей в стиле `cp`: `0:/dir/file` — абсолютный путь, `/dir` — относительный по отношению к корню диска, простое имя попадает в текущую папку; конечный символ `/`, существующий каталог или группа из нескольких файлов означают «каталог, сохранить исходные имена», в остальных случаях последний компонент становится новым именем.

Каждое диалоговое окно полностью повторяет внешний вид DOS Navigator — серый фон, белая двойная рамка, чёрные поля ввода, зелёные кнопки, красные буквы горячих клавиш и полностью непрозрачный курсор (ничто с игрового экрана не просвечивает через модальное окно, и ничего с панели под ним — например, прокручивающееся длинное имя — тоже не просвечивает). Поля ввода используют стандартную раскладку клавиатуры США, так что ты можешь вводить пути, имена и маски напрямую (`Shift`+`8` даёт `*` и так далее).

## Панель меню и система настроек

Нажатие `F9` (или щелчок по зелёному заголовку) вызывает **панель меню** DOS Navigator: **Files · Play · Tape · Options · Help** (пункты на экране английские). Стрелки влево/вправо перемещают между верхними меню; `Enter`/стрелка вправо открывает выпадающее меню; у **Options** есть вложенное подменю **Settings**. Прямо в меню живут «динамические пункты» — параметры, у которых значение показано тут же в строке. Поведение продумано:

- **Стрелки «влево»/«вправо» позволяют настраивать числовые (диапазонные) параметры на месте** — громкость, затемнение OSD, положение окна, чувствительность MP3 — с мелким шагом, при этом ты не выходишь из меню.
- **Выбор (НЕТ/ДА, режим воспроизведения и т. д.) переключается только с помощью клавиш `Пробел` или `Enter`**; клавиши «Влево»/«Вправо» при выборе перемещают тебя между верхними меню, так что ты всегда можешь выйти из него.
- **Чувствительность MP3** имеет широкий диапазон (0–4096), поэтому вместо того, чтобы пролистывать его, клавиши `Пробел`/`Enter` открывают специальный **диалог ввода чисел с встроенным пояснением** того, за что отвечает этот параметр.

Все настройки сохраняются в файле **`0:/bulbulator.ini`**, который записывается при нажатии `Options → Save`. Среди них: скорость/задержка прокрутки, стиль папок, отображение скрытых файлов, режим воспроизведения, пауза при воспроизведении музыки, поведение при запуске, навигатор при загрузке, громкость, затемнение OSD и координаты окна (X/Y).

## Кассетная станция — независимый от платформы загрузчик PULSE

На шаге 14 добавляется настоящая кассетная станция. Она загружает **`.tap` / `.tzx`** (стандартные блоки ПЗУ и турбо-/пользовательские загрузчики), а также **оцифрованные кассетные записи в форматах `.wav` и `.mp3`** — именно над этим пришлось потрудиться больше всего.

Конструкция соответствует независимому от аппаратной платформы **классу PULSE** в контракте загрузчика. ARM хранит всю информацию о форматах и отправляет поток импульсов `{уровень, продолжительность в T-состояниях}` в асинхронный FIFO; модуль фабрики **`tape_player.v`** воспроизводит их, синхронизуясь по сигналу разрешения T-состояния самого процессора (`pe3M5_core`). Поэтому лента и процессор работают в **точной синхронизации** — пауза (HALT) останавливает их обоих, так что циклы синхронизации ROM, турбо-режима или пользовательского загрузчика измеряют импульсы точно так же, как если бы они поступали с настоящей ленты. Фабрика просто измеряет фронты; она понятия не имеет, что такое «пилотный сигнал».

- **Считыватель — это точная модель физической магнитной головки**, а не эквалайзер: разделительный конденсатор (мягкий фильтр верхних частот — снимает постоянное смещение, но пропускает каждый быстрый фронт), компаратор Шмитта с гистерезисом и субсэмпловая интерполяция пересечения нуля для точного тайминга турбо. Именно это и позволяет прочитать MP3-запись кассеты, снятую хоть на телефон.
- **Автоопределение пилота** решает, кассета это или музыка, сканируя начало записи на пилот-тон. **`MP3/WAV as tape`** принудительно включает кассетный путь — для турбо-рипов или обрезанного пилота, который детектор мог бы пропустить.
- При загрузке MP3 станция сначала **пропускает разминочный кадр декодера и сводит постоянную составляющую считывателя** ещё до первого импульса, так что пилот-тон начинается чисто — без щелчка в начале.
- **`Tape Sound`** включает/выключает звук загрузки (монитор ленты). **`Mute machine on load`** — отдельная опция: глушит *собственный* звук машины на время загрузки (ULA Спектрума воспроизводит сигнал EAR через свой бипер — так и на живой машине, но теперь это можно выключить), переводя аудио-мукс на плеер. **`MP3 sens`** настраивает гистерезис детектора фронтов.
- Маркер **`T`** появляется в строке состояния (там, где находится значок режима воспроизведения музыки), как только аудио распознается как кассета.
- Быстрая остановка (`Backspace`) **очищает FIFO импульсов**, поэтому немедленный перезапуск всегда начинается с начала файла, а не с оставшегося импульса.

## Музыкальный плеер

Плеер из шага 13 был интегрирован и расширен. Он воспроизводит **`.psg`** (AYUMI с программным синтезом AY-3-8910), **`.mp3`** (minimp3) и **`.wav`** (PCM), передискретизируя их до частоты HDMI 47996 Гц (speexdsp), а также передаёт PCM в аудио-FIFO через мультиплексор плеера (`AUDIO_CTRL`).

- **Неблокирующий кольцевой буфер** обеспечивает непрерывное воспроизведение музыки даже во время длительного копирования или удаления файлов.
- **Режимы воспроизведения** (`F2` или `Play → Mode`): FOLDER, FILE, FOLDER LOOP, FILE LOOP, RANDOM.
- **Неблокирующая пауза/возобновление** работает с битовой точностью (регистры AY, огибающая и LFSR шума сохраняются во время паузы — никаких щелчков). Функция **запуска с приостановкой** возвращает мультиплексор системе, сохраняя при этом позицию трека.
- **Предварительная загрузка MP3** (в меню «Воспроизведение») загружает весь файл в DDR, благодаря чему воспроизведение не прерывается при остановках из-за сборки мусора на SD-карте.
- **Громкость** регулируется в реальном времени с помощью клавиш `+`/`-` на цифровой клавиатуре (и в меню «Options»): коэффициент усиления 0..255 на выходе HDMI, отображается как `Vol:NN%` в верхней строке.
- **Строка состояния** (строка 22) показывает воспроизводимый трек с пиктограммой воспроизведения/паузы и текущим режимом воспроизведения; в верхней панели всегда отображается тип машины и зелёный/красный индикатор работы/паузы.

## Управление машиной и координация звука

- **Пауза** (`F10` / PS/2 Pause) замораживает Spectrum, не захватывая экран. Маска остановки (ручная пауза / остановка из-за музыки / заморозка на SD-операции) владеет тактами машины и снимается только вручную.
- **`Pause on music`** останавливает машину, пока играет музыка; **`On launch (music)`** выбирает MACHINE (приглушить музыку, звук машины слышен) или MUSIC (оставить музыку, машина без звука), когда программу запускают поверх играющей музыки; **`Boot nav`** выбирает, показывать ли навигатор при включении или машина стартует сразу (войти позже — `F12`).
- Большой прозрачный знак **PAUSE** (символ-полоска и слово одной высоты, в правом верхнем углу, на прозрачном фоне, без прямоугольника позади) появляется, когда машина заморожена — на отдельном баннер-слое.
- **`F11`** — это полный сброс машины; видеосигнал не зависит от сброса ядра.

## Регистры плоскости управления

Управляющая плоскость AXI прирастает регистрами полноцветного OSD и кассетной станции; версия фабрики поднимается до **`0xB01B0017`**:

| Адрес | Название | R/W | Значение |
|---|---|---|---|
| `0x00` | `VERSION` | R | `0xB01B0017` |
| `0x04` | `IJ_CTRL` | W | бит 0 = HALT (заморозка тактов машины) |
| `0x08` | `IJ_STAT` | R | бит 0 = HALT_ACK, бит 1 = RAM_BUSY |
| `0x48` | `OSD_CTRL` | W | бит 0 = включение OSD с разрешением 1 бит на пиксель, бит 1 = включение цветного OSD с DDR |
| `0x54` | `KBD_DATA` | R | `{break[9], empty[8], code[7:0]}`; чтение опустошает FIFO PS/2 |
| `0x5C` | `KBD_HB` | W | сигнал «deadman» (любая запись); шлюз перенаправляет нажатия клавиш на Z80, если ARM перестаёт реагировать |
| `0x60` | `MACHINE_ID` | R | идентификатор загруженного ядра |
| `0x6C` / `0x70` | `OSD_OP` / `OSD_POS` | W | непрозрачность / положение OSD (1 бит на пиксель) |
| `0x74` | `VOL` | W | коэффициент усиления громкости на выходе HDMI 0..255 |
| `0x78` | `AUDIO_CTRL` | W | бит 0 = 1 — мультиплексировать PCM с ARM-плеера на HDMI, 0 = аудио из фабрики/машины |
| `0x7C` / `0x80` | `AUDIO_FIFO` / `AUDIO_STAT` | W/R | отправка образца PCM `{R,L}` / флаги «пусто» и «заполнено» |
| `0x84`–`0x90` | `BANNER_*` | W | наложение независимого баннера состояния/PAUSE (включение / адрес / данные / позиция) |
| `0x94` | `OSD_DDR_BASE` | W | байтовый адрес DDR для цветового холста ARGB8888 |
| `0x98` | `DDR_OSD_POS` | W | положение цветного холста OSD (независимо от `OSD_POS`) |
| `0x9C` | `TAPE_CTRL` | W | бит 0 — воспроизведение, бит 1 — ear_mux, бит 2 — отключение звука |
| `0xA0` | `TAPE_FIFO` | W | добавление `{level[31], duration[23:0] в T-состояниях}` |
| `0xA4` | `TAPE_STATUS` | R | бит 0 = FIFO заполнен, бит 1 = воспроизведение |

## Сборка, прошивка, запуск

**Собери битстрим.** `./build.sh` → `sources/build/bulbulator_zx_loader.bit`. На этом шаге в фабрику добавляются DDR-считыватель цветного OSD (`osd_ddr_rd`), правки композитора и кассетная станция (`tape_player.v`). А ещё `assemble.sh` накладывает наш патч watchdog-ресинка PS/2 (`third_party/atlas-zx-ps2-watchdog/ps2.v`) поверх скачанного ядра Atlas — так чистый клон пересобирает ровно тот битстрим, что стоит на плате.

**Скомпилируй приложение для ARM.** `cd arm && ./build_loader.sh` → `loader.elf`. Оно компилируется с использованием рабочей области Vitis BSP, подключает FatFs (xilffs), драйвер SD (`xsdps`), AYUMI, minimp3 и ресемплер speexdsp, а также использует настраиваемый файл `lscript.ld`, который включает D-кеш и резервирует некешируемое окно DDR для холста.

**Прошивка по JTAG и запуск.** Скрипт прошивки конфигурирует битстрим через PCAP (преобразуя его в `.bit.bin` через `bootgen`, как в шагах 6–13), затем загружает и запускает `arm/loader.elf` на Cortex-A9 №0. Версия фабрики в регистре `0x00` должна читаться как `0xB01B0017`.

**Загрузка с SD (без хоста, без JTAG).** Скомпилируй FSBL, битстрим и загрузчик в файл `BOOT.BIN` с помощью `flash/build_boot.sh`, скопируй его в загрузочный раздел FAT карты, подключи для загрузки с SD и включи питание.
