# BulbuLator — умный загрузчик лент (HANDOVER для разработки)

Документ для подключения помощников. Цель подсистемы: **грузить ЛЮБУЮ ленту (.tap/.tzx) на максимально быстрой скорости и гарантированно без сбоев**, автоматически выбирая режим под конкретный загрузчик. Ниже — как оно устроено, где что лежит, как собрать/прошить/протестировать, что уже работает и что осталось.

> Актуальная прошивка: **v0.15.77**, бит **0xB01B003E**. Плата EBAZ4205 (Zynq-7010) + Platform Cable USB II (JTAG, hw_server:3121) на ThinkPad (`ssh thinkpad`, юзер lavrinovich). Мак = только пульт по ssh.
> ⚠️ ROM-trap (Model A freeze+inject) RETIRED в v0.15.76→77: убран из меню (заменён на Smart load), ветка удалена из tape_start, opt_romtrap форсится в 0. Не возрождать. Урок: мёртвую фичу, чей флаг стоит первым в диспетчере загрузки, мало спрятать из UI — застрявший флаг=1 (мейлбокс/конфиг) блокирует ВСЕ загрузки; удалять ветку.

## 1. Три режима загрузки

Реальный Z80 (T80) крутится в ПЛ; ARM = control plane. Лента может грузиться тремя способами:

| Режим | Что делает | Для чего | Скорость |
|-------|-----------|----------|----------|
| **SMART (byte-inject)** | Фабрика подменяет тело ROM-подпрограммы LD-BYTES (0x0562-0x0574) своим циклом; ARM подаёт декодированные байты блока прямо на шину данных по хендшейку. Реальный ROM хранит их и сам ставит carry (SCF) | Стандартный ROM-загрузчик (`LOAD ""`, BASIC + CODE) | Мгновенно (без пилота/кромок/полос) |
| **PULSE replay** | ARM парсит .tap в импульсы → кольцо → 1мс-ISR → FIFO фабрики → `tape_ear`. CPU читает `IN 0xFE` как настоящую ленту | Кастомные турбо-загрузчики (свой код читает ленту сам) | 1× / 4× / 8× (warp) |
| **WARP** | Разгон всего ядра (SAFE 4×) или только CPU (FAST 8×) поверх PULSE | Ускорение импульсной загрузки | до 8× (потолок клока) |

**Ключевая идея v0.15.74 — АВТО-КЛАССИФИКАТОР:** старт всегда в SMART; если игра/демка передала управление СВОЕМУ загрузчику (читает `IN 0xFE` сам, не через ROM), фабрика это видит и прошивка на лету переключается на PULSE для остатка ленты.

## 2. Как классификатор различает случаи

Три поведения после того, как SMART скормил первые блоки (обычно BASIC-загрузчик):

1. **Чистый стандарт** (TRAPTEST, ALIENS): каждый блок запрашивается через ROM LD-BYTES → `byte_wait` приходит → SMART кормит все блоки → готово. Мгновенно.
2. **Стандарт + анимация** (BigThings): ROM-загрузчик для ВСЕХ блоков, но между блоками играет анимация (LD-BYTES делает DI, анимация идёт на 50Гц-прерывании В ПАУЗАХ — поэтому «не привязана к скорости CPU»). Паузы до нескольких секунд, в них НЕТ чтений ленты (byte-inject заменил LD-EDGE) → ждём `byte_wait` с щедрым таймаутом (20с backstop). Мгновенно, анимация играет.
3. **Кастом-загрузчик** (EXOLON): BASIC POKE-ит машинный загрузчик в верхнюю память (напр. 0xFD26) и прыгает туда; тот читает `IN 0xFE` сам, ROM LD-BYTES не зовёт → `byte_wait` НЕ придёт никогда. Фабрика видит **tight/edge-correlated чтение порта FE** (`sampling_active`) → прошивка за ~0.5с переключается на PULSE-реплей с текущего блока.

**Дискриминатор (финал v0.15.75) = ТЕМП чтений порта FE `SMP_CNT`@0xB0 (первичный) + `sampling_active` TAPE_STATUS bit3 (вторичный).** Прошивка меряет за окно 0.5с: `fe_reads > 800 (≈1600/с) ИЛИ sampling_active≥2/3` → кастом-загрузчик → PULSE-fallback; иначе (пауза BigThings) ждать `byte_wait`.
- Почему сырой RATE, а не только `sampling_active`: v0.15.74 экспонировала только `sampling_active` (tight-poll <64T ИЛИ edge-correlated) — и **пропустила EXOLON**: его loader читает FE НЕ тесно (>64T между чтениями), а под SMART импульсов нет → edge-corr=0 → sampling_active=0. Поэтому v0.15.75 добавила сырой счётчик `SMP_CNT` (каждое чтение FE, без гейта тесноты).
- Замеры на железе (порог 800 разделяет с огромным запасом): **EXOLON ferate≈27000/0.5с (~54000/с) → PULSE**; **BigThings пауза ferate≈220/0.5с (~440/с = спорадичный клавиатурный скан) → остаётся SMART**. Тюнинг/диагностика: `g_dbg_ferate`@мейлбокс+0x38 (последний замер окна).
- ⚠️ Если кастом-загрузчик читает FE РЕДКО (медленный поллинг, <1600/с) И не тесно — оба сигнала могут не сработать → smart дойдёт до 20с backstop и всё равно свалится в pulse (медленно, но грузит). Кандидат в задачу: Deflector (грузится на pulse, но не на smart — проверить его ferate).

## 3. Где код

### RTL (правки — ТОЛЬКО в мастерах, см. гочу сборки §6)
- **`cores/zx/src/main.v`** — byte-inject FSM + мукс шины данных.
  - Порты: `byte_ready`, `tape_dout[7:0]`, `allow_turbo` (вход), `byte_wait` (выход).
  - `turbo` (де)защёлкивается ТОЛЬКО на M1-фетчах (`~m1 & ~mreq`): engage на 0x0556, disengage вне 0x0556..0x0574. Иначе запись `LD (IX),A` кладёт IX на шину адреса и ложно сбрасывает.
  - `tape_stub[0:18]` = инжектируемый цикл (LD A,D/OR E/JR Z / JR-спин / LD A,byte / LD (IX),A / INC IX / DEC DE / JR / POP HL / SCF / RET).
  - req/ack через `served`-флаг: одно хранение на импульс `byte_ready`.
- **`sources/axi_ctl.v`** — AXI-регистры:
  - `TAPE_CTRL` 0x9C (W): бит7 `smart_en`, бит8 `byte_ready`, [16:9] байт (+ старые pulse-биты [6:0], [4:3] fmode, бит5 sync).
  - `TAPE_STATUS` 0xA4 (R): бит0 full, бит1 playing, бит2 `byte_wait`, **бит3 `sampling_active`** (новое в 0x3D).
  - `MEMWR_CNT` 0xAC (R): счётчик записей в RAM (верификация загрузки).
- **`sources/bulbulator_zx_ddr_top.v`** — CDC (aclk↔spclk 2-FF для smart-сигналов), `sampling_active` синк spclk→aclk (`samp_a1`), инстанс axi_ctl + main. VERSION = `0xB01B003E`. Готовый детектор загрузчика: `smp_edge`/`smp_tight`/`edge_corr_active`/`sampling_active` (строки ~499-545) — переиспользован классификатором.

### Прошивка (ARM, bare-metal)
- **`arm/loader_main.c`** (мастер на ThinkPad; рабочая копия — Mac scratchpad).
  - `smart_tape_load()` — грузит .tap: открывает файл в `g_tapbuf`, автостарт (фантомный ENTER в 128-меню), обходит блоки, кормит ДАННЫЕ каждого блока (пропуск флага[0] и паритета[последний] = DE=len-2) по хендшейку. Классификатор в step-1 wait. Метка `smart_fallback_pulse` = переключение на PULSE с текущего блока.
  - `tape_start()` — роутинг: форс `opt_romtrap=0` (ROM-trap retired, ветки нет), затем `opt_smartload` → smart_tape_load, иначе pulse.
  - NC-мейлбокс `KMB=0x0F700000` (некэшируемое окно — JTAG-poke доходит до core0, в отличие от кэш-глобалов): `opt_smartload@+0x34`, `opt_fastload@+0x1C`, `opt_wavfast@+0x20`, `g_autotrig@+0x00`, `g_fs_*`, `g_autodir@+0x100`, `g_autoname@+0x180`, `g_fs_path@+0x200`, `g_fs_out@+0x800`.
  - `fs_service()` cmd 9 (debug) = карта блоков .tap в `g_fs_out` (флаг/длина/тип/имя/параметры).

### KVM (веб-пульт по JTAG, ThinkPad /tmp)
- `zxstream2.py` (:8088) — веб-UI: экран, файл-браузер, клавиши, опции. Чекбокс **SMART LOAD** (`opt` cmd). Запуск `startsrv.sh`.
- `zxctl.tcl` — JTAG-петля: читает экран → `/tmp/scr.bin`, исполняет очередь `/tmp/cmdq/*.cmd`. Запуск `startloop.sh`. Опции: массив `OPT` имя→адрес.
- `gen_addrs.sh` → `zxaddrs.tcl`: адреса (мейлбокс хардкожен, кэш-символы через `nm`).

## 4. ROM-факты (128-1.rom = 48K BASIC ROM, проверено xxd)

```
0556 INC D / 0557 EX AF,AF' (A'=флаг) / 0559 DI / 055C OUT (FE),A / 055E LD HL,053F / 0561 PUSH HL
0562 IN A,(FE)      <- вход loop LD-BYTES; SMART инжектит своё тело с 0x0562
05E2 RET
05E7 LD-EDGE-1: цикл сэмпла IN A,(FE) на 0x05F1, RET NC/Z на 0x05F4/0x05EE  <- сюда виснет ROM-загрузчик без импульсов
0603 SCF / 0604 RET
```

SMART engage на 0x0556 (регистровое `turbo` даёт +1 такт, к 0x0562 уже 1); тело 0x0562-0x0574; carry авторит сам ROM реальным SCF (Model A с ковкой carry через DIRSet — ЗАКРЫТ, латчи ALU/flag не пишутся через регистровую шину).

## 5. Сборка / прошивка / тест (всё на `ssh thinkpad`)

```bash
# синтез бита (~3.5мин, только при правке sources/**/*.v или cores/zx/src/*.v):
cd ~/bulb-v13/research/15-pentagon && source /tools/Xilinx/Vivado/2023.1/settings64.sh && ./build.sh

# пересборка прошивки (после правки arm/loader_main.c):

cd ~/sdboot/ws/loader/Debug
arm-none-eabi-gcc -O0 -g3 -c -mcpu=cortex-a9 -mfpu=vfpv3 -mfloat-abi=hard \
  -I~/sdboot/ws/browser/Debug/_sdk/bsp/ps7_cortexa9_0/include -o src/main.o ../src/main.c
bash /tmp/build_loader.sh && cp loader.elf.new loader.elf   # link

# прошивка (PCAP бит + dow loader.elf, ассертит VERSION):
bash /tmp/reload3a_usb.sh          # ждёт ">>> STEP assert-version: OK PL=0xB01B003E"
```

### Диагностика по JTAG (xsct, non-halting где возможно)
- Z80 PC: `mwr 0x40000004 1; poll 0x40000008&1; read 0x400000EC` — **ХАЛТИТ CPU** (0x40000004 = IJ_CTRL), только для снапшота, не в живой загрузке.
- MEMWR: read `0x400000AC` (растёт = грузится/работает; ~0 = спин/пауза).
- TAPE_STATUS `0x400000A4`: бит2 byte_wait, бит3 sampling_active.
- Карта блоков .tap: cmd 9 (пиши путь в `0x0F700200`, `mwr 0x0F700004 9`, читай `g_fs_out` @ `0x0F700800`).
- Экран: `mrd -bin -file scr.bin 0x40008000 1728` (6912Б ZX-скрин, GP-BRAM зеркало). Рендер в ASCII — питон-хелперы в /tmp.

### Тест-ленты на SD (проверены)
- `0:/loadtest/TRAPTEST.tap` — крошечный стандарт (`10 PRINT "TRAPOK"`), эталон SMART.
- `0:/loadtest/ALIENS.TAP` — реальная игра, стандарт.
- `0:/demos/demo48/BigThings.tap` — стандарт+анимация (6 блоков, паузы). SMART, анимация играет.
- `0:/games/best-tested-tap/EXOLON_KONSTANTIN_KALANTAI.tap` — кастом-загрузчик (4 блока, 2 безголовых). Гибрид SMART→PULSE.

## 6. ГОЧИ (обязательно)

- **🔴 Сборка затирает build/:** `build.sh`→`assemble.sh` делает `rm -rf sources/build` и пересобирает. `build/zx` = симлинк на `cores/zx` (правки main.v ВЫЖИВАЮТ), но `bulbulator_zx_ddr_top.v` + `axi_ctl.v` КОПИРУЮТСЯ из мастеров `sources/*.v`. **Правь top.v/axi_ctl ТОЛЬКО в `sources/*.v`, main.v — в `cores/zx/src/main.v`.** НЕ в `sources/build/`.
- **D-cache ON (Шаг 13):** JTAG-poke в кэшируемые глобалы НЕ доходит до core0. Управляющие переменные — в NC-мейлбоксе (KMB=0x0F700000). Кэш-глобалы по JTAG читать нельзя (врут).
- **Чтение Z80 PC халтит CPU** — не годится для детекции в живой загрузке. Потому классификатор на `sampling_active` (неинтрузивно).
- **macOS `sed -i`** — BSD-синтаксис, молча не работает; правь через Edit-tool или python.
- **Фоновые процессы в `ssh thinkpad '... &'`** рвут SSH-сессию — запускай через `nohup ... >log 2>&1 &` и проверяй состояние отдельной командой.
- **Версионирование:** `BULB_FW` в loader_main.c = v0.STEP.PATCH (патч на каждый билд). PL VERSION (0xB01B00xx) в top.v = битстрим; бампать при правке RTL + синхронно в `/tmp/reload3a_usb.sh` (ассерт).
- **История билдов:** `research/15-pentagon/BUILD_HISTORY.md` — строка на билд.

## 7. Статус и что дальше

**Работает (проверено на железе по JTAG):**
- SMART: TRAPTEST (печатает TRAPOK), ALIENS (титул), BigThings (грузится + анимация играет).

- Авто-классификатор по sampling_active (v0.15.74) — быстрое (~0.5с) переключение вместо 20с.

**Открытые задачи (для помощников):**

2. **Больше тест-лент** — прогнать библиотеку, собрать матрицу «загрузчик → рабочий режим/скорость», занести в этот файл.
3. **8× потолок** — тесный турбо капнут физикой клока (whole-core 4×); задокументировано в памяти.

**Что уже выполнено:**
- **TZX Smart Load (Сделано 14.07.2026):** Формат TZX теперь полноценно поддерживается в умном загрузчике. Стандартные (0x10), турбо (0x11) и дата-блоки (0x14) напрямую пробрасываются в байт-инжект ПЛИС. Мета-блоки пропускаются. TZX больше не сваливается принудительно в PULSE!
- **Авто-снижение скорости PULSE-фазы (Сделано 14.07.2026):** Реализована авто-классификация загрузчика по `g_dbg_ferate` (кол-ву чтений порта FE). Если юзер включил 8x Warp, а загрузчик медленный (<10000 чтений/0.5с), прошивка принудительно снижает скорость до 1x. Если средний (<20000) — до 4x. Это гарантирует надежность нестандартных таймингов.

**Философия (владелец):** никогда не урезать функционал; всё лучше/богаче; макс.скорость + гарантия без сбоев. Флаг `SMART LOAD` (F9-меню и веб-KVM) — опция, дефолт OFF; для кастома, где smart не помог, всегда есть PULSE/SPEED вручную.
