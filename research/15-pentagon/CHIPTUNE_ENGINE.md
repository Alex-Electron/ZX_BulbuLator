на 0x170 доказать нашу музыку невозможно.

а расширенные банки Пентагона `0x0FE00000` лежат ВНУТРИ диапазона FS_BUF. Модуль на 4 МБ,
прочитанный в FS_BUF, затрёт банки машины. Линкер отдаёт под кэшируемое DDR всё до `0x0F600000`
(`arm/lscript.ld`).

## 1. Архитектура: один интерфейс источника

### 1.1 Куда встраивается

Ничего в реальном времени не меняем. **Потребитель (`player_isr_tick`) и микшер остаются как есть** —
это та самая стабильность, которая только что закрыта (щелчки, антипоп, догон GS). Весь чиптюн живёт
на стороне ПРОИЗВОДИТЕЛЯ: рендерит в то же кольцо `rb_*`, которое ISR уже умеет вычерпывать.

```
   [файл на SD] --f_read (открытие)--> [образ в ОЗУ] --разборщик--> [рендер] --rb_push--> [кольцо 10.9 с]
                                                                                              |
   [General Sound: своя очередь 85 мс, как сейчас] ------------------------------------------>|
                                                                                              v
                                             player_isr_tick (1 мс) -> FIFO фабрики -> ЦАП 47996
```

`FMT_PSG` перестаёт быть особым случаем и становится ОДНИМ из источников чиптюна.

### 1.2 Интерфейс

```c
typedef struct {                         /* всё, что источник сообщает о себе */
    char     title[64], author[64];
    int      subtunes, subtune_cur;
    unsigned total_frames;               /* 0 = длительность неизвестна (зацикленная музыка) */
    int      chips;                      /* сколько микросхем в миксе (1..3): AY×2, SID×3 */
    char     chipname[4][8];             /* "AY","SID","SAA" — для окна плеера и приборов */
} snd_info;

typedef struct {
    const char* name;                                            /* "PT3", "PSID", "XM" */
    int  (*probe )(const uint8_t* img, uint32_t len, const char* ext);   /* по сигнатуре, не по имени */
    int  (*open  )(const uint8_t* img, uint32_t len, snd_info* out);     /* образ уже в ОЗУ */
    int  (*render)(int16_t* dst, uint32_t frames);               /* стерео @47996, 0 = конец */
    int  (*subtune)(int n);
    void (*meters)(uint8_t pk[4], uint32_t wr[4]);               /* пик и число записей на чип */
    void (*close )(void);
} snd_src;
```

**Жёсткие правила интерфейса** (это и есть «звук — реальное время»):

1. **`render()` не имеет права трогать файловую систему, кучу и часы.** Ни `f_read`, ни `malloc`,
   ни `XTime_GetTime`. Только чтение из образа в ОЗУ и запись в буфер. Всё дорогое — в `open()`.
2. **Файл читается ЦЕЛИКОМ при открытии** (`f_read` в свой буфер, не в `FS_BUF`). Чиптюны мелкие:
   PT3/VTX/YM — единицы-десятки КБ, `.ay` — до 64 КБ, SID — обычно <64 КБ, XM/IT — до 4 МБ.
   Это строго лучше нынешнего стриминга WAV: у RAM-источника не бывает срыва по паузе карты.
3. **Темп задаёт только счётчик сэмплов**, как уже сделано у PSG (`render_one_psg`, `p_samples`
   против `g_next_frame_at`) — никаких «раз в 20 мс по таймеру».
4. **Многочиповость решается внутри источника:** N экземпляров модели, сложение и деление на N перед
   выдачей. Наружу источник всегда отдаёт готовое стерео. Микшер оболочки об этом ничего не знает.
5. **Пик по каждому чипу и счётчик записей в него источник ведёт сам** (`meters`) — без этого
   многочиповый SID недоказуем (см. раздел 4).

### 1.3 Форматы и разборщики

| Путь | Форматы | Разборщик | Бэкенд |
|---|---|---|---|
| A. Готовый дамп регистров | PSG (есть), VTX, YM2!–YM6!, VGM(AY8910) | распаковка + подача кадров; VTX и YM оба сжаты **LHA lh5** — один депакер на оба | ayumi ×1..2 |
| B. Покадровый трекер | PT3, PT2, STC, ASC, STP | либо интерпретатор на C, либо **штатный плеер автора на Z80** (см. ниже) | ayumi ×1..2 |
| C. Z80-код в файле | `.ay` (EMUL) | 64 КБ ОЗУ, INT 50 Гц, перехват OUT на `#FFFD/#BFFD` | z80emu (уже есть) + ayumi |
| D. Трекерные модули | MOD, S3M, XM, IT | libxmp-lite | свой микшер библиотеки |
| E. SID | PSID/RSID (v1..v4) | 6502 + 64 КБ + разбор заголовка | модель SID ×1..3 |

**Решение по пути B:** у нас в репозитории уже лежит `player/pt3_gasman.asm` — ШТАТНЫЙ плеер PT3
Бульбы. Гонять его на z80emu дешевле и точнее, чем писать интерпретатор паттернов на C: вызов `play`
раз в кадр — это тысячи тактов Z80 при бюджете 70 тыс. тактов на кадр 3.5 МГц, то есть доли процента
ядра, и результат бит-в-бит совпадает с оригиналом (никаких «у меня орнаменты чуть иначе»).
Тот же приём закрывает PT2/STC/ASC теми же плеерами. Интерпретатор на C писать только там, где
плеера-эталона нет.

Итого путь B и путь C сводятся к ОДНОМУ механизму: «Z80 + ОЗУ + перехват портов AY», отличается лишь
то, откуда взялся плеер (из файла или наш вшитый). Это ещё и снимает риск «эмулятор не тот» —
z80emu уже отлажен на General Sound.

### 1.4 Диспетчер в навигаторе

`is_music_ext` (`loader_main.c:3983`) расширяется таблицей расширений, но **выбор источника — по
сигнатуре содержимого** (`probe`), а не по имени. Причина известна: FatFs регистронезависим, а имена
в мейлбоксе режутся на 96 символах (`NAMELEN`), то есть по имени формат определять нельзя в принципе.
Открытие: прочитать файл → `probe` по очереди → `open` → `track_arm()` (существующий путь, gapless и
антипоп работают без правок).

### 1.5 Память

| Буфер | Где | Размер |
|---|---|---|
| Образ файла (все форматы, кроме тяжёлых трекеров) | статически в `.bss` (кэшируемое DDR) | 512 КБ |
| Образ трекерного модуля + распакованные сэмплы | отдельный статический регион в кэшируемом DDR | 4–6 МБ |
| ОЗУ виртуальной машины источника (Z80 64 КБ / 6502 64 КБ) | `.bss` | 128 КБ |
| Обмен с ВТОРЫМ ЯДРОМ | OCM `0xFFFF0000` (некэшируемая) | ≤56 КБ |

**Запрещено:** класть образы в `FS_BUF 0x0F900000` (перекрывается с банками Пентагона `0x0FE00000`)
и в мейлбокс `0x0F700000`. Читать надо `f_read` прямо в свой буфер. Кэшируемость здесь правильная:
эти байты трогает только ARM, фабрика их не видит.

## 2. Второе ядро: что выносить, а что нет

Сейчас второе ядро НЕ используется вовсе — в `loader_main.c` нет ни одного упоминания
`cortexa9_1`/CPU1 (проверено грепом). BSP для него собран только ради lwIP.

### 2.1 Правила раздела

| На ядре 0 (как сейчас) | На ядре 1 (новое) | Никогда на ядре 1 |
|---|---|---|
| Прерывание-потребитель 1 мс, микшер, FIFO фабрики | `render()` тяжёлых источников: SID ×1..3, трекерный микс, ayumi ×N, Z80-плееры | FatFs и SD |
| FatFs, навигатор, OSD, ввод | ничего больше | Любые регистры GP0/AXI, PCAP, `pl_reload` |
| General Sound целиком (протокол с машиной) | | `printf`, куча, общая с ядром 0 |
| Разбор файла, `open()`, смена трека | | Часы фабрики/таймеры, привязанные к ЦАП |

Причина запрета на AXI со второго ядра прямая: все известные нам способы заморозить плату
(полуоткрытый бёрст в `S_AXI_HP0`, потеря отладочного APB, гонки на смене ядра) живут именно на шине
к фабрике. Ядро 1, которое умеет только считать в DDR и класть сэмплы в кольцо, не может испортить
ничего, что не чинится его же перезапуском.

**General Sound на второе ядро НЕ переносим сейчас**, хотя он и самый дорогой: его цикл — это
рукопожатие с машиной через регистры фабрики (`0x174/0x178/0x180`), и мы только что закрыли там
гонку извлечения из FIFO. Перенос возможен позже и только в виде «ядро 0 делает весь регистровый
обмен, ядро 1 крутит Z80 и сэмплы по общей очереди команд» — отдельная работа, не попутная.

### 2.2 Механика передачи

* Ядро 1 пишет готовое стерео в **SPSC-кольцо в НЕкэшируемой памяти** (OCM 0xFFFF0000, 56 КБ =
  ~0.3 с). Индекс `w` двигается ТОЛЬКО ПОСЛЕ данных — то же правило, которым закрыта гонка CDC в
  фабрике («нагрузку держать, флаг отдавать позже данных»), просто в софте.
* Ядро 0 в `player_pump` копирует из этого кольца в основное `rb_*` (копия 192 КБ/с — ничто).
  Потребитель не меняется вообще.
* Некэшируемость — сознательный выбор вместо возни с SCU/shareable: PCM-поток 192 КБ/с в обе стороны
  ничего не стоит, а любая ошибка в когерентности L1 даёт треск, который потом ищут неделю.
* **Старт:** штатный AMP-путь Zynq (адрес приложения в `0xFFFFFFF0` + `SEV`). Область
  `0xFFFFE000..0xFFFFFFFF` не занимать — там вектор BootROM.
* **Своё DDR:** ядру 1 отрезается регион понижением `LENGTH` в `arm/lscript.ld` (например,
  ядро 0 до `0x0E000000`, ядро 1 `0x0E000000..0x0F5FFFFF` = 22 МБ). Это правка линкера — предусловие,
  а не попутная работа.

### 2.3 Как не сломать звук

1. **Сторож.** Ядро 1 инкрементирует счётчик-сердцебиение каждый проход. Ядро 0 в `player_pump`
   проверяет; нет движения 100 мс → плавно гасим (`a_target=0`) и **переключаемся на рендер своим
   ядром** (тот же `render()`, вызванный с ядра 0). Деградация в «тише и дороже», а не в тишину.
2. **Кольцо 10.9 с не трогаем.** Оно и есть страховка от любых задержек ядра 1.
3. **Отзывчивость даёт СБРОС кольца, а не мелкое кольцо.** Смена субтрека/трека уже сделана через
   рампу + `rb_r = rb_w` (`source_teardown_muxup`). Уменьшать глубину ради «мгновенной реакции»
   нельзя: главный цикл на ядре 0 надолго уходит в обход каталога SD.
4. **Никакой плавающей точки в прерывании.** Рендер (а он у ayumi на `double`) остаётся в
   производителе. Если когда-нибудь понадобится VFP на ядре 1 — там своё, чужого контекста нет.
5. **Порядок при смене ядра ПЛИС:** `pl_reload` останавливает ядро 1 ДО QUIESCE (иначе оно будет
   гнать сэмплы в кольцо, пока фабрики нет).

### 2.4 Когда включать второе ядро

**Не раньше фазы 6.** Фазы 1–5 (см. ниже) по оценкам укладываются в ядро 0 с запасом, а любая AMP-
конструкция — это новый класс отказов. Второе ядро включаем ровно тогда, когда прибор покажет, что
одного не хватает: 3SID с качественным фильтром.

Оценки цены по процессору (ориентиры, **мерить, а не верить**): ayumi — единицы процентов на чип;

10–20 % на чип; SID цикл-точный с нелинейным фильтром — 25–45 % на чип. 6502 в SID почти бесплатен
(2–8 тыс. тактов из 19656 за кадр).

**Порядок внутри SID тоже важен:** сначала целочисленная (фикс-пойнт) модель, потом качество. На A9
без NEON-оптимизации `double`-фильтр съест втрое больше, чем нужно.

## 4. Приёмка: чем доказывать музыку, а не шум

Правило владельца — «не объявлять музыку рабочей без положительного отсчёта» — здесь расширяется:
**положительный отсчёт нужен на КАЖДОМ чипе**.

### 4.1 Приборы

| Прибор | Где | Что доказывает |
|---|---|---|
| `0x17C` пик ARM-ноги (биты 23:16) | фабрика | сэмплы дошли от ARM до фабрики (не «программа думает, что играет») |
| `0x17C` пик итогового микса (биты 7:0) | фабрика | нет клиппинга после суммирования; 127 подряд = перегруз |
| `g_underruns`, `g_rb_min` | `player.c:117,118` | кольцо не пустело: `g_underruns=0`, `g_rb_min` заметно >0 |
| пик на чип `pk[0..3]` + число записей в регистры `wr[0..3]` | новое, в источнике | какой именно чип звучит и звучит ли вообще |
| бюджет рендера, мкс на секунду звука | новое, счётчик в производителе | честная доля ядра; по нему решается вопрос второго ядра |
| сердцебиение ядра 1 | новое, OCM | ядро 1 живо |

Символы читать по свежему ELF (`arm-none-eabi-nm loader.elf | grep`): **адреса сдвигаются при каждой
сборке**, старый список даст мусор.

### 4.2 Сценарии

1. **Тишина — это отсчёт 0.** Перед стартом трека `0x17C` бит 23:16 обязан быть 0. Если он не ноль,
   любой последующий «положительный отсчёт» ничего не доказывает.
2. **Ноты видно.** На известном треке пик ARM-ноги гуляет в такт музыке (снимать 10 отсчётов
   за 5 с). Постоянное «127» = шум/клиппинг, постоянное «3» = почти тишина.
3. **Повторяемость.** CRC32 первых 10 с PCM (считать в производителе) на одном и том же файле
   совпадает между запусками и между сборками. Разошлось — регрессия, и видно, на каком именно файле.
4. **Хостовой стенд** по образцу `arm/gs_host_fx_test.c`: те же исходники источника собираются на
   ThinkPad, рендерят WAV. Слушать и сверять CRC там, а не на плате. Это снимает 90 % отладки с платы.
5. **Отрицательный контроль.** Заглушить чип N → его пик падает в 0, микс меняется. Без этого
   «все три пика ненулевые» может означать один и тот же сигнал, размноженный ошибкой.
6. **Долгий прогон.** Час плейлиста: `g_underruns` = 0, `g_rb_min` не съезжает, память не растёт.

### 4.3 Многочиповый SID отдельно

* **Разбор заголовка печатать в приборы:** `secondSIDAddress` (+7A, v3+), `thirdSIDAddress` (+7B, v4),
  адрес = `$D000 | (байт << 4)`, допустимы только чётные `0x42..0x7F` и `0xE0..0xFE`
  (то есть `$D420..$D7E0` и `$DE00..$DFE0`); 0 = чипа нет; третий не может совпадать со вторым.
  Модели чипов — из `flags` (+76): биты 4-5 первый, 6-7 второй, 8-9 третий (`01`=6581, `10`=8580).
* **Диспетчер адресов проверять на хосте юнит-тестом:** запись в `$D420` обязана попасть ТОЛЬКО во
  второй чип, в `$D400` — только в первый. Счётчик записей на чип это и показывает.
* **Приёмка 2SID/3SID:** на известном многочиповом треке из HVSC все N счётчиков записей растут и все
  N пиков ненулевые. Один нулевой счётчик = диспетчер не разложил адреса (самая вероятная ошибка).
* **Ловушка:** трек, объявленный как 3SID, может реально использовать третий чип не с первой
  секунды. Проверять на треке, где это известно, а не на первом попавшемся.

## 5. Лицензионная чистота

**Расхождение, которое надо закрыть первым.** В `bulb-v13` корневой `LICENSE` — **MIT**, а
`THIRD_PARTY.md` в репозитории **нет вовсе** (проверено `find`). Решение по проекту (и постановка
задачи) — **GPL-2.0-or-later**. До вендоринга любого GPL-кода (reSID, libsidplayfp) это надо привести
в порядок, иначе получится поставка со смешанной и неверно заявленной лицензией.

**Правила вендоринга** (как у `arm/z80emu/ВЕНДОРЕНО.md`): каталог в `third_party/`, файл
`ВЕНДОРЕНО.md` с источником, версией/SHA, лицензией и списком наших правок; запись в `THIRD_PARTY.md`;
префикс символов при риске совпадения имён (образец — `-DRANDOM_PREFIX=bulb` у speexdsp).

**Урок про подмену именем действует и в C:** два вендоренных дерева с одинаковыми именами файлов или
символов — это молчаливая подмена, ровно как `saa1099.sv`/`saa.v` в битстриме. Каждый новый источник
собирать отдельным объектным файлом и проверять карту символов на дубли.

## 6. Риски

1. **AMP-подъём второго ядра** — новый класс отказов (когерентность L1, старт, зависание). Смягчение:
   он нужен только с фазы 6, есть сторож и откат на рендер ядром 0.
2. **Память под трекеры.** XM/IT до 4 МБ. Положить их в `FS_BUF` — значит затереть банки Пентагона.
   Нужен отдельный регион и правка линкера; правка линкера трогает всех.
3. **Оценки процессора могут не сойтись.** Все цифры выше — ориентиры из чужих замеров. Первым делом
   в фазе 0 делается счётчик бюджета рендера, дальше решения принимаются по нему.
4. **Зависание виртуальной машины источника.** `.ay` и SID могут уйти в бесконечный цикл. Нужен предел
   тактов на кадр и состояние «плеер умер» с плавным гашением, иначе повиснет главный цикл.
5. **Лицензионный узел** (раздел 5): пока корень MIT и нет `THIRD_PARTY.md`, вендорить GPL-код нельзя.
6. **Регресс уже закрытого звука.** Любая правка `player_isr_tick` — красная зона. Проект сознательно
   построен так, что потребитель не меняется вообще.
7. **`0x170` вместо `0x17C`.** Если приёмку делать по 0x170, чиптюн будет «не звучать» при исправном
   тракте: этот прибор наполняет машина.
