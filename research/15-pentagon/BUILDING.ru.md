# Шаг 15: сборка из исходников

Languages: [English](BUILDING.md) · **Русский**

Это полный путь от чистого клона до платы, которая загружается: ядра FPGA, прошивка оболочки ARM, загрузочный образ и SD-карта. Если хочешь просто попробовать, тебе ничего из этого не понадобится: готовые файлы находятся в [`bitstreams/`](bitstreams/), а куда их класть, написано в главном [README](../../README.ru.md#как-попробовать).

Всё, что здесь описано, было проверено на практике: свежий `git clone`, затем эти команды, на Ubuntu 26.04 с Vivado 2023.1. Ядро ZX, собранное таким образом, совпадает байт в байт с `bitstreams/ATLAS_B0200.bit.bin`.

## Что тебе понадобится

- **Linux.** Команды написаны на bash. Vivado работает и на Windows, но приведённые здесь скрипты там не тестировались.
- **Vivado 2023.1.** Бесплатная версия Standard поддерживает `XC7Z010`. В ней есть `vivado` и `bootgen`.
  Перед сборкой запусти `source /tools/Xilinx/Vivado/2023.1/settings64.sh` (подправь путь под свою установку).
- **Только для прошивки ARM:** Vitis 2023.1 (для `xsct` и исходных кодов драйверов) и `arm-none-eabi-gcc`
  с newlib, например пакеты Ubuntu `gcc-arm-none-eabi` и `libnewlib-arm-none-eabi`.
- `git`, `python3` и около 1 ГБ свободного места на диске для клонирования и одного дерева сборки.

## 1. Загрузи исходники

```sh
git clone https://github.com/Alex-Electron/ZX_BulbuLator.git
cd ZX_BulbuLator
./get_deps.sh
```

Скрипт `get_deps.sh` загружает сторонние ядра в каталоги `cores/` и `deps/`, каждое из которых привязано к конкретному коммиту: ядро Atlas ZX, ядро hdl-util HDMI, ядро MiSTer ZX (несколько модулей у нас с ним общие) и библиотека Digilent. Он клонирует только HDL и не требует инструментов Xilinx.

## 2. Сборка ядер FPGA

Есть два ядра: ZX и NES. Оба собираются из одного и того же дерева, а скрипт `sources/assemble.sh` собирает это дерево в папку `research/15-pentagon/sources/build/`. **`assemble.sh` каждый раз очищает каталог `sources/build/`**, поэтому скопируй готовый битстрим перед сборкой следующего.

**Ядро ZX (Atlas): 48K, 128K и Пентагон.** Главное из двух.

```sh
research/15-pentagon/build.sh
# -> research/15-pentagon/sources/build/bulbulator_zx_loader.bit
```

На ноутбуке с 16 потоками и 64 ГБ оперативной памяти это занимает примерно четыре минуты. Когда всё закончится, проверь в логе две вещи. Тайминг должен быть закрыт, и не должно быть предупреждения `[Synth 8-9873]`: оно означает, что два файла определили модуль с одинаковым именем, и более поздний из них незаметно заменил первый (так однажды в битстрим попала немая заглушка звукового чипа).

```sh
cd research/15-pentagon/sources/build
grep -i "timing constraints are" vivado.log     # expect: All user specified timing constraints are met.
grep "CRITICAL WARNING.*8-9873" vivado.log      # expect: nothing
```

**Ядро NES / Денди:**

```sh
research/15-pentagon/sources/assemble.sh
cd research/15-pentagon/sources/build
vivado -mode batch -source build_nes.tcl
# -> bulbulator_zx_loader_nes.bit
```

Опубликованный файл `bitstreams/NES_CE29.bit.bin` — это ядро NES, которое работает на моей плате. Текущие исходные коды собирают версию CE30, которая отличается от неё общей оболочкой и пока не проверялась на плате.

Чтобы сравнить свою сборку с опубликованной, преобразуй обе в формат `.bit.bin` (см. ниже) и сравни: сам файл `.bit` содержит дату сборки в заголовке, а файл `.bit.bin` — нет.

**Перевод ядра для карты.** Оболочка загружает ядра в FPGA во время работы через PCAP, а PCAP требует формат `.bit.bin`:

```sh
research/15-pentagon/flash/bit2bin.sh research/15-pentagon/sources/build/bulbulator_zx_loader.bit
# -> .../bulbulator_zx_loader.bit.bin  (goes to 0:/CORES/ATLAS.BIT.BIN)
```

## 3. Сборка прошивки оболочки ARM

Прошивка находится в файле `arm/loader.elf`. В репозитории уже есть готовая версия; вот как её пересобрать.

Для этого понадобятся две вещи, которые не входят в репозиторий. **Vitis 2023.1** — ради `xsct` и исходников драйверов Xilinx (по умолчанию путь `/tools/XilinxVitis/Vitis/2023.1`, переопредели его с помощью `VITIS=`). А ещё **`arm-none-eabi-gcc` с newlib** в `PATH`: опубликованная прошивка была скомпилирована с помощью `gcc-arm-none-eabi` 14.2.rel1 и `libnewlib-arm-none-eabi` 4.6.0 из Ubuntu, а не с помощью компилятора из Vitis.

```sh
research/15-pentagon/arm/bsp/make_bsp.sh      # platform + both BSPs -> research/15-pentagon/arm/bsp/ws
research/15-pentagon/arm/build_loader.sh      # -> research/15-pentagon/arm/loader.elf
```

Скрипт `make_bsp.sh` работает примерно 30 секунд. Он запускает `xsct` с файлом `bsp/create_platform.tcl` и описанием аппаратного обеспечения `bsp/ebaz4205_ps7.xsa`, после чего создаёт два домена: в ядре 0 запускается оболочка (standalone, FatFs настроен на длинные имена и exFAT), а ядро 1 получает lwIP 2.1.3 для сетевой панели. Затем он применяет два патча из папки `bsp/patches/` к драйверам ядра 0, которые нужны для платы без линии card-detect: сокращённый таймаут SD и повторная инициализация с повторной попыткой при сбое чтения или записи на SD. `build_loader.sh` компилирует оболочку с использованием этой рабочей области.

Параметры: `WS=<dir>` перемещает рабочую область в другое место (укажи тот же `WS` в `build_loader.sh`), `FORCE=1` пересоздаёт уже существующую, а `MAKE_XSA=1` сначала пересобирает файл `.xsa` в Vivado на основе настроек PS7 из файла `bsp/ps7_params.tcl` (только процессорная часть, без битстрима, занимает около 20 секунд).

При использовании указанных выше версий компилятора загружаемый образ совпадает с опубликованным байт в байт (сравни вывод команды `arm-none-eabi-objcopy -O binary`). Сами файлы `.elf` отличаются только отладочной информацией, в которой записаны абсолютные пути сборки. `build_loader.sh` кладёт результат поверх готового `arm/loader.elf`,
поэтому после сборки git показывает этот файл изменённым; так и должно быть.

**Начальный загрузчик** `flash/fsbl.bin` поставляется в готовом виде. `make_bsp.sh` также собирает FSBL для Zynq в `$WS/ebaz/zynq_fsbl/fsbl.elf`, но с FCLK0 по умолчанию вместо 100 МГц, как требует проект. Его таблицы инициализации PS7 совпадают с поставляемым файлом байт в байт, а вот код — нет (поставляемый собран другим компилятором), и загрузку с ним на плате не проверяли, поэтому используй поставляемый файл `fsbl.bin`. Если хочешь попробовать:

```sh
cd $WS/ebaz/zynq_fsbl
sed -i -E 's/EMIT_MASKWRITE\(0XF8000170, 0x03F03F30U ?, ?0x00800800U\)/EMIT_MASKWRITE(0XF8000170, 0x03F03F30U ,0x00400400U)/g' ps7_init.c
rm -f *.o fsbl.elf && make
arm-none-eabi-objcopy -O binary fsbl.elf fsbl.bin
```

## 4. Создание загрузочного образа

Файл `BOOT.BIN` — это то, что BootROM платы считывает с карты: начальный загрузчик (FSBL), битстрим и прошивка.

```sh
research/15-pentagon/flash/mkboot_zx.sh \
    research/15-pentagon/sources/build/bulbulator_zx_loader.bit  BOOT.BIN  [path/to/loader.elf]
```

Если третий аргумент не указан, используется файл `arm/loader.elf` — готовая прошивка из репозитория. FSBL — это `flash/fsbl.bin`, тот же, что и в шаге 14. Скрипту нужны `bootgen` (из `PATH` или задай `BOOTGEN`) и `arm-none-eabi-objcopy`.

bootgen записывает имя файла битстрима в образ, поэтому загрузочный образ отличается от `bitstreams/BOOT_B0200_v0.15.448.BIN` на несколько байтов, если исходный файл не имеет такого же имени. Собранный из опубликованных файлов, он совпадает байт в байт:

```sh
cp research/15-pentagon/bitstreams/ATLAS_B0200.bit /tmp/B0200.bit
research/15-pentagon/flash/mkboot_zx.sh /tmp/B0200.bit /tmp/BOOT.BIN
cmp /tmp/BOOT.BIN research/15-pentagon/bitstreams/BOOT_B0200_v0.15.448.BIN && echo identical
```

## 5. Запись на карту

**С помощью кард-ридера (простой способ).** Отформатируй карту microSD в формате FAT32 и скопируй файлы так, как показано в [таблице в главном README](../../README.ru.md#как-попробовать): `BOOT.BIN` в корне, ядра `.bit.bin` в папке `CORES/`, наборы ПЗУ — в папке `ROMS/`. Полная раскладка — в [`docs/SDCARD.ru.md`](docs/SDCARD.ru.md). Плата должна быть один раз настроена на загрузку с карты с помощью одного резистора: смотри [Шаг 0](../00-setup/).

**При обновлении ядра ZX меняй и `BOOT.BIN`, и `CORES/ATLAS.BIT.BIN`.** При холодном запуске ядро загружается из `BOOT.BIN`, а при переключении машин в меню оно перезагружается из `CORES/`. Обновишь один — будешь через раз работать на старом ядре.

**Через JTAG, не вынимая карту.** Для этого понадобится JTAG-кабель ([Шаг 0](../00-setup/)), `hw_server`, работающий на порте 3121, и прошивка, уже запущенная на плате с открытым навигатором: пока открыто меню или идёт лента, прошивка вообще не обслуживает хост. Три правила, каждое оплачено незагружающейся платой:

1. сначала запиши под **временным** именем;
2. проверь его размер **в списке каталога**, а не в поле «записано», которое показывает неверные данные, когда карта
   заполнена;
3. только потом переименуй его, заменив настоящий файл.

```sh
xsdb research/15-pentagon/tools/put_retry.tcl BOOT.BIN 0:/BOOT.NEW
xsdb research/15-pentagon/tools/card_ls.tcl 0:/
xsdb research/15-pentagon/tools/card_mv.tcl 0:/BOOT.BIN 0:/BOOT.BAK
xsdb research/15-pentagon/tools/card_mv.tcl 0:/BOOT.NEW 0:/BOOT.BIN
```

`put_retry.tcl` перед каждой попыткой проверяет буфер передачи и после записи снова считывает файл, потому что прошивка использует этот же буфер для чтения своих файлов.

**Никогда не запускай `rst -system` на работающей плате.** ПЛИС продолжает писать в DDR, пока процессор находится в состоянии сброса, в результате чего недописанный бёрст застревает, и изображение зависает, пока ты не отключишь питание.

## 6. Проверь, что работает

В верхней строке навигатора отображаются версии прошивки и ядра, например `v0.15.448 / b0200`. Тот же номер ядра можно прочитать в регистре `0x00` плоскости управления (`0xB01B0200`).
