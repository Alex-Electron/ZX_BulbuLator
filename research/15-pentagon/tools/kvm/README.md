# Веб-КВМ платы по JTAG

Смотреть, что на плате, не подходя к телевизору: экран машины + живые счётчики в браузере.

    tmux new -d -s kvm  "./run_probe.sh"        # опрос под супервизором (xsdb вылетает - см. ниже)
    tmux new -d -s http "python3 kvm.py"        # http://<хост>:8088

- `kvm_probe.tcl` держит ОДНО подключение xsdb и пишет в `/tmp/kvm` кадр зеркала экрана и пакеты
  регистров; `kvm.py` разбирает пакеты и рисует страницу. Кнопок ввода намеренно нет: инжект идёт в
  матрицу Z80 мимо гейта OSD и может перебить работу владельца в интерфейсе.
- **Супервизор обязателен:** xsdb ВЫЛЕТАЕТ, когда цель исчезает из JTAG (прошивка, `rst -system`), и
  никакой `catch` внутри скрипта этого не спасает.
- **Перед прошивкой положить `/tmp/kvm/pause`** - опрос отпустит отладочный канал. Два клиента xsdb
  НЕ делят DAP: одновременный `rst -system` из другого сеанса роняет и его, и сам сброс (лечится
  `sources/jtag_revive_dap.tcl`).

## Замеры JTAG, из которых сделана конструкция

| Что | Время |
|---|---|
| одно слово (`mrd`) | **17 мс** |
| блок 6912 Б (зеркало экрана) | **119 мс** |
| кадр из DDR 57984 Б | **804 мс** |

Отсюда: регистры читаются ПАКЕТАМИ (мейлбокс 0x80..0xC4 и блоки 0x00/0xA0/0x140 - четыре трансфера
вместо тридцати обращений), а кадр неизбежно «рваный» по вертикали на анимации - за 119 мс луч
проходит около шести кадров, синхронизации с ним у отладочного канала нет. Tearing-free КВМ будет
только по Ethernet (задача #18).

## Гоча раскладки экрана ZX

`y = (a>>11 & 3)*64 + (a>>5 & 7)*8 + (a>>8 & 7)`. Третье слагаемое - номер строки ВНУТРИ символа, а
не блок из восьми; перепутав их местами, получаешь узнаваемую, но нечитаемую кашу (проверено).
