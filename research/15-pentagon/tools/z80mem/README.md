# Тесты памяти машины НА САМОЙ МАШИНЕ (инжект Z80 по JTAG)

Оплачено битой памятью Пентагона: приёмку памяти обязана проходить САМА МАШИНА, а не ARM — у
ARM-овской стороны мастера памяти нет пересечения тактовых доменов, поэтому она чиста даже когда
машинный путь врёт (так и было до ядра B0074: 5-10 % чтений расширенных банков возвращали байт
предыдущей транзакции).

Запуск: `export PATH=/tools/Xilinx/Vivado_Lab/2023.1/bin:$PATH && xsdb <файл>.tcl`
Результаты машина складывает в экранную область банка 5, её видно с хоста:
`mrd -bin -file /tmp/z80res.bin 0x40008000 1728` (зеркало экрана, 6912 Б).

| Файл | Что делает | Где ответ |
|---|---|---|
| `memtest63.tcl` | заливает 256 байт в каждый банк (перебор ВСЕХ значений 7FFD, знание раскладки не нужно) шаблоном `v XOR смещение`, потом сверяет | число расхождений по банку в `0x5800+банк`, маркер конца `0xE7` в `0x4A00` |
| `pushtest.tcl` | заливает 16 КБ банка 8 шаблоном `LD SP,#0000` + 128×64 `PUSH HL` — ровно так льёт UMT v2.3x (две записи в 3 такта) | число расхождений в `0x5800` |
| `readtest.tcl` | ЧИСТОЕ чтение банка 8 дважды в экран — сверяется с содержимым DDR (`mrd 0x0FE20000`), ловит именно путь ЧТЕНИЯ | байты в `0x4000` и `0x4100` |

Гочи, каждая стоила ложного вывода:
- **банк 2 заливать НЕЛЬЗЯ** — в окне 0x8000 лежит сам инжектированный код (иначе «ошибки» на исправном
  железе; у меня так дважды вышло «56 расхождений в каждом банке»);
- сверять надо ВСЕ восемь байтовых линий: смещения 0 и 0x3FFF банка — это линии 0 и 7 из восьми;
- расширенные банки (8..63) живут в DDR и НЕ обнуляются ни F11, ни сбросом из меню — перед прогоном
  писать заведомо другую затравку;
- раскладка: `банк[5:0] = {7FFD[5], 7FFD[7], 7FFD[6], 7FFD[2:0]}` (совпадает с UMT 1-в-1).
