# General Sound на ARM: разбор референса и план (06.08.2026)

Выбор устройства сделан раньше (`AUDIO_NEXT_DECISION.md`): TurboSound-FM не влезает в фабрику, а
General Sound по своей природе — отдельный компьютер со своим процессором и памятью, то есть ровно то,
что естественно живёт на ARM, а не в ПЛИС. Ниже — модель, снятая с ЖИВОГО апстрима
(`MiSTer-devel/ZX-Spectrum_MiSTer/rtl/gs.v`, 255 строк), а не с вендоренной копии.

## Что такое GS по железу

| | |
|---|---|
| процессор | Z80, у MiSTer разогнан до 28 МГц (оригинал 12 МГц) |
| ПЗУ | 32 КБ (`gs105b`, прошивка 1.05b) |
| ОЗУ | до 4096 КБ, страницами по 32 КБ |
| прерывание | 37 480 Гц (у MiSTer фазовый аккумулятор от 56 МГц) |
| каналы | 4 × 8 бит PCM, у каждого 6-битная громкость |
| выход | L = канал1+канал2, R = канал3+канал4 |

### Порты со стороны Спектрума (всего два)

- `#xxBB` — запись: команда. Чтение: слово состояния, `бит7` = флаг данных, `бит0` = флаг команд.
- `#xxB3` — запись: данные. Чтение: байт, отданный GS'ом.

Протокол **явно флаговый**: Спектрум пишет команду и опрашивает состояние, пока GS не подтвердит. Это
важно для нас — значит задержка ARM (десятки-сотни микросекунд) протокол не ломает, софт просто ждёт
флага. Именно так и написано в описании порта: регистр состояния существует, чтобы узнать, «можно ли
прочитать или записать очередной байт данных, или подать очередную команду».

### Внутренние порты (видит только Z80 внутри GS), `A[3:0]`

| порт | смысл |
|---|---|
| 0 | выбор страницы ОЗУ, биты 5:0 (страница 0 = ПЗУ) |
| 1 | чтение команды от Спектрума |
| 2 | чтение данных от Спектрума |
| 3 | запись байта для Спектрума |
| 4 | чтение слова состояния |
| 5 | сбросить бит0 состояния |
| 6..9 | громкость каналов 1..4 (6 бит) |
| A | бит7 состояния := НЕ бит0 порта 0 |
| B | бит0 состояния := бит5 порта 6 |

### Как в каналы попадает звук

Отдельных портов у каналов нет: **сэмпл защёлкивается САМ при чтении процессором памяти в окне
`0x6000..0x7FFF`**, а номер канала берётся из адреса — `A[9:8]`. Байт при защёлкивании
переворачивается в знаковый: `{~d[7], d[6:0]}`. Это ключевая деталь, без неё эмуляция даст тишину.

### Карта памяти GS

```
0x0000-0x3FFF  первые 16 КБ ПЗУ
0x4000-0x7FFF  первые 16 КБ первой страницы ОЗУ
0x8000-0xFFFF  листаемые страницы по 32 КБ (0 = ПЗУ, 1 = первая страница ОЗУ, 2.. = ОЗУ)
```

## Как это раскладывается у нас

### В фабрике — только ловушка портов (десятки LUT, не тысячи)

Отвечать на `IN` за такт шины ARM не может, поэтому по образцу моста дисковода в фабрике живут теневые
регистры, а ARM их обслуживает:

- `port_BB` (команда от Спектрума) и `port_B3` (данные от Спектрума) — защёлки на запись, ARM читает.
- слово состояния — **биты держит сама фабрика**, ровно по правилам из `gs.v`: чтение `#B3`
  сбрасывает бит7, запись `#B3` ставит бит7, запись `#BB` ставит бит0; ARM снимает биты своими
  подтверждениями. Так протокол остаётся корректным при любой задержке ARM.
- `port_03` (байт от GS к Спектруму) — регистр на запись со стороны ARM, Спектрум читает напрямую.

Итого: два байтовых регистра, два бита, декод адреса. Это единственное, что добавляется в ПЛИС, и
поэтому GS можно делать НЕ дожидаясь разгрузки LUT (см. `RESOURCE_SQUEEZE.md`).

### На ARM — сам GS

1. **Z80-интерпретатор** на втором ядре. Бюджет: оригинальные 12 МГц ≈ 3 млн инструкций/с, то есть
   около 200 такт ARM на инструкцию Z80 при 667 МГц. Табличный интерпретатор укладывается в 50-150.
   **Это главный риск, и он измеряется, а не обсуждается:** первым делом бенчмарк инструкций/с на
   плате, и только потом всё остальное.
2. **Память:** 32 КБ ПЗУ + до 1 МБ ОЗУ в PS DDR. Осторожно с миной из PROJECT_RULES.md: окно расширенных
   банков Пентагона `0x0FE00000` лежит внутри диапазона fs-буфера — под GS брать отдельную область и
   зафиксировать её в карте памяти.
3. **Микшер:** на каждый выходной сэмпл L = ch1·vol1 + ch2·vol2, R = ch3·vol3 + ch4·vol4. Прерывание
   37 480 Гц эмулируем счётчиком такта Z80, а не таймером ARM.
4. **Вывод:** через тот же путь, что музыкальный проигрыватель (audio FIFO в фабрике). Когда играет
   GS, проигрыватель не работает, так что конфликта нет — но микширование с AY машины надо проверить
   по факту, а не предположить.

### Приёмка

Правило владельца: **не объявлять музыку рабочей без пик-метра.** У нас есть `AUD_DBG` (0x170) с
пиками по источникам за окно 74 мс. Под GS нужен свой слот; тишина ничего не доказывает, нужен
положительный отсчёт при играющем модуле и ноль при остановленном.

## Порядок работ

1. Бенчмарк Z80-интерпретатора на плате (инструкций/с на втором ядре, D-cache ON). **Стоп-точка:**
   если не выходит 3 млн/с — GS в реальном времени не поедет, и это надо знать до всего остального.
2. Ловушка портов в фабрике + слот пик-метра. Одна сборка.
3. Эмулятор: ПЗУ, страничность, внутренние порты, защёлкивание каналов по чтению `0x6000..0x7FFF`.
4. Микшер и вывод, приёмка по пик-метру на настоящем GS-модуле.
