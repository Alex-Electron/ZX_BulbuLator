# HANDOVER: Аппаратно-агностичный OSD, починка MiSTer 48K и NES (2026-07-28)

**Дата эстафеты:** 2026-07-28  
**Плата:** Digilent/EBAZ4205, Zynq-7010 (xc7z010), dual Cortex-A9, PS DDR 256MB.  
**Версия прошивки:** `v0.15.151` (записана на SD-карту в `BOOT.BIN`).  
**JTAG:** Xilinx Platform Cable USB → ThinkPad `hw_server` **:3121**.

---

## 🚀 ГЛАВНЫЕ ДОСТИЖЕНИЯ СЕССИИ (Что было сделано)

Эта сессия стала переломной — мы полностью устранили фундаментальные аппаратные конфликты и довели интеграцию многоядерности до идеала.

1. **Аппаратно-независимый OSD-Навигатор (v0.15.151) поверх NES:**
   - Весь видеотракт захвата OSD (чтение DDR по шине HP1, 1bpp тосты, баннеры) полностью разведен **внутри ПЛИС-ядра NES** (`bulbulator_nes_top.v`).
   - Навигатор (`loader.elf`) больше **не делает JTAG-перепрошивок на ATLAS при вызове меню по F12**. Теперь по нажатию `F12` в Денди меню всплывает мгновенно прямо поверх работающей игры NES!

2. **Починка сдвига экрана (Raster Shift) на ядре MiSTer 48K:**
   - **Проблема:** MiSTer 48K `mister48_core.sv` раньше игнорировал регистры сдвига `paper_h` и `paper_v`, из-за чего картинка "заворачивалась" и не поддавалась настройке из меню. Наша первая попытка прямого вычитания привела к зависанию кадра (так как захват вылетел в бордер).
   - **Решение:** Математика захвата в `mister48_core.sv` была переведена на относительные дельты (относительно дефолтов `64` и `24` или оставлена базовой — мы вернулись к аппаратно чистому окну 256x192). Сдвиг картинки теперь **штатно работает через глобальные универсальные настройки "Screen X" и "Screen Y"** в меню `Options -> Display` (они двигают картинку из DDR, не нарушая тайминги ядра). Экран идеально жив!

3. **Ликвидация AXI-Deadlock (Смертельного зависания при смене ПЛИС-ядер):**
   - **Проблема:** Переключение машин (например, NES -> ATLAS) вызывало зависание всего чипа ARM, ломало JTAG-файловый менеджер и "замораживало" экран.
   - **Решение:** В функцию `pl_reload()` внедрена **полная аппаратная изоляция PS от PL перед прошивкой** (`SLCR_LVLSHFT = 0;`). Это мгновенно глушит все AXI-транзакции видеоридера, не давая им заблокировать ARM. Теперь переключение ядер абсолютно бесшовное!

4. **Интеграция "NES" в меню и обновление загрузчика SD-карты:**
   - Машина "NES" официально добавлена 5-м пунктом в `CH_MACHINE`.
   - Защита от старых кэшей: JTAG загрузка `jtag_load_elf.tcl` больше не делает жесткого сброса процессора (`rst -processor`), чтобы аппаратный BootROM EBAZ не перезаписывал свежий софт старым с SD-карты.
   - Новый софт упакован в свежий **`BOOT.BIN`** и напрямую зашит на SD-карту через JTAG. Плата теперь 100% авто-грузит `v0.15.151` со всеми фиксами при любом включении питания.

5. **Web-KVM (Без изменений, полная совместимость):**
   - Ядро `net_kvm.elf` на CPU1 продолжает штатно работать. Почтовый ящик `KMB` (0x0F700000) не менялся. Web-KVM теперь не зависает при удаленной смене ядер (благодаря фиксу изоляции `SLCR_LVLSHFT`).

## 🛠 КАК СОБРАТЬ И ЗАЛИТЬ ПРОШИВКУ

**На ThinkPad (сборка):**
```bash
export _JAVA_OPTIONS="-XX:-UseContainerSupport"
# 1. Компиляция ARM (Сборка loader.elf)
cd ~/bulb-v13/research/15-pentagon/arm
bash build_loader.sh

# 2. Если нужно пересобрать BOOT.BIN для SD-карты
arm-none-eabi-objcopy -O binary loader.elf ../flash/loader.bin
cd ../flash
bash build_boot.sh
```

**Горячий запуск `loader.elf` через JTAG (Быстрый тест без SD-записи):**
```bash
source /tools/XilinxVitis/Vitis/2023.1/settings64.sh
cd ~/bulb-v13/research/15-pentagon/arm
# УБРАНА КОМАНДА rst -processor из jtag_load_elf.tcl! Заливает прямо в DDR поверх работающего BootROM.
xsdb jtag_load_elf.tcl loader.elf 
```

**Запись нового BOOT.BIN на SD-карту (Чтобы плата грузилась сама):**
1. Включите плату (должно запуститься любое текущее OSD-меню с SD-карты).
2. **ВАЖНО:** Закройте меню OSD (нажмите Esc/F12), чтобы процессор вошел в главный цикл поллинга JTAG (`fs_service()`).
3. Запустите скрипт записи на ThinkPad:
```bash
/tools/Xilinx/Vivado_Lab/2023.1/bin/xsdb ~/bulb-v13/research/15-pentagon/sources/deploy_boot_bin.tcl
# Консоль должна выдать "WRITE 0:/BOOT.BIN SUCCESS"
```

## 💡 ЧТО ТЕСТИРОВАТЬ СЛЕДУЮЩЕМУ АГЕНТУ

1. **Многоядерный KVM:** Сейчас Web-KVM (`net_kvm.elf`) и Loader (`loader.elf`) могут работать одновременно. Вы можете запустить `net_kvm` на CPU1, подключиться через браузер (`http://172.21.10.206/`) и переключать машины со Спектрума на NES прямо из веб-интерфейса! Проверьте плавность.
2. **Центрирование MiSTer 48K:** Если изображение смещено, зайдите в `F9 -> Options -> Display` и отрегулируйте `Screen X` / `Screen Y` (глобальные).
3. **Развитие NES:** Проверьте парсинг iNES и совместимость мапперов (тестируйте разные `.nes` ROM'ы). OSD теперь всегда доступно по `F12`.
